## 1. 测试目的与范围

本报告记录 v0.1.1 阶段对快递袋正常循环状态、状态修正盘点单号字段移除、库存与调拨并发防护的验证结果，并汇总本阶段后端单元测试覆盖情况。测试用于检查所列功能和场景，不替代后续完整集成、压力、部署及安全测试。

验证重点包括：状态修正不再要求手填盘点单号，仍校验原因、角色和状态转换；盘点无差异时提交即闭环并记录闭环时间；调拨建单只接受归属源站的空闲袋；调拨建单与状态修正并发时，袋级行锁和事务校验阻止两方同时成功；接口幂等不重复推进数据版本；库存初始化并发互斥与幂等缓存事务边界由单元测试覆盖。

## 2. 测试环境与方法

- 后端服务：`http://localhost:8090`。
- 数据库并发验证：使用真实 MySQL 数据执行并发请求；本地部署目标为 MySQL 8.0。测试日期为 2026-10-07。
- 单元测试：Maven Wrapper 执行干净 `clean verify`，共 294 项测试。
- 覆盖率：JaCoCo 行覆盖率门禁沿用现有配置；既有 DTO、Entity、配置与启动引导类排除口径未收窄，未通过扩大排除范围提升覆盖率。
- 接口功能回归：按实际 REST 请求和响应验证 48 项检查，包括状态修正、角色拒绝、幂等回放、盘点闭环、调拨源站校验及台账读取。
- 并发功能回归：5 轮真实 MySQL 双请求竞争，分别并发提交调拨建单与同袋状态修正；这用于验证并发正确性，不是吞吐量或响应时间测试。

## 3. 测试结果

| 测试项 | 结果 | 证据与说明 |

| 后端单元测试 | 通过 | 干净 `clean verify`：294/294 项通过 |
| JaCoCo 行覆盖率 | 达标 | 5,459 / 7,678 行，71.1%，高于 70% 要求 |
| 状态机分支覆盖率 | 达标 | 状态机包分支覆盖率 100% |
| 全局分支覆盖率 | 记录 | 54.24%；全局分支率不作为本次 70% 行覆盖门禁的替代指标 |
| REST 接口功能回归 | 通过 | 48 项检查全部通过 |
| 调拨与状态修正并发 | 通过 | 5 轮均只有一方成功；本次各轮调拨建单成功、状态修正返回 4110（袋已被未出库调拨引用） |
| 盘点无差异闭环 | 通过 | 无差异盘点提交后状态为 `CLOSED`，`closedAt` 已记录 |

接口功能回归还确认：状态修正可不提供盘点单号，原因仍为必填；普通用户状态修正被 2001 拒绝；相同请求幂等回放不会重复推进版本；同站同态修正以 4102 拒绝无变化操作，跨站同态修正允许改变归属；调拨建单拒绝不属于源站的袋。测试袋报废通过合法状态流转路径完成，维修中的袋使用“维修完成且无法修复”路径转报废。

盘点差异袋清单仍是实物核验候选，不会自动创建状态修正或建立盘点单与修正记录的自动闭环关联。盘点单号继续作为盘点业务单号保留；出库业务单据使用的盘点差异引用也属于独立逻辑。

## 4. 缺陷处置与复核范围

本阶段审查和回归过程中发现的实现问题已修复并纳入相应验证：状态修正关联订单缺失或乐观更新失败时事务拒绝提交；库存及在持数 Redis 副作用延迟到事务提交后；调拨建单与状态变更共用袋行锁并复核活动调拨引用；调拨建单校验袋的当前归属站点；库存重建未取得初始化互斥标记时不删除已有库存键；写事务中的幂等完成结果在数据库提交后写入，回滚时清理处理中占位；相同 clientRequestId 的并发请求未取得 SETNX 时返回可重试错误。

以上结论限于本报告所列代码版本、用例和测试环境。通过这些测试不能证明系统不存在其他缺陷或安全问题。

## 5. 未覆盖事项与后续安排
