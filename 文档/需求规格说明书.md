## 1 引言

### 1.1 编写目的

本文档依据《本科毕业设计任务书》（2026-09-01 下发）与《共享快递袋系统设计与实现 系统设计说明书》V1.5 编制，明确共享快递袋系统的功能需求、非功能需求、业务规则与验收标准，作为系统设计、编码实现、测试用例设计与最终验收的依据。

本文档预期读者：指导教师、答辩评审专家、毕业生本人，以及后续参与实现与维护的开发人员。文档与《系统设计说明书》《数据库设计说明书》《测试报告》构成一套互相追溯的交付物：本文档定义"做什么"，系统设计说明书定义"怎么做"，数据库设计说明书定义"数据怎么存"，测试报告验证"做到了没有"。

### 1.2 项目背景

随着电子商务与快递业务规模持续增长，一次性快递包装消耗量大、回收率低，过度包装与包装废弃物污染问题日益突出。国务院《固体废物综合治理行动计划》（国发〔2025〕14 号）明确提出"加快推进快递包装绿色转型，加强商品过度包装治理"；GB/T 39084-2020《绿色产品评价 快递封装用品》、GB/T 16606.2-2018 与 GB/T 16606.3-2018《快递封装用品》系列标准对快递封装用品的绿色评价与技术要求作出了规定。上述政策与标准为快递包装由一次性消耗向循环共用转变提供了依据。

共享快递袋以循环复用方式替代一次性包装，是上述转型的可行路径之一。但其投放、取用、回收、消毒、复用等环节目前普遍依赖线下人工登记，暴露出**库存信息不透明、流转过程不可追溯、站点间调度依赖经验、损坏与遗失责任难以认定**四类突出问题，亟需通过信息化系统予以支撑。

本系统面向校园、社区、写字楼等快递集散场景，以共享快递袋为循环载体，通过信息化手段实现快递袋**分配、使用、回收、消毒、调度**的全流程在线管理，形成"取—用—还—洗—调"闭环。系统结合网络空间安全专业培养方向，在认证、鉴权、数据保护与操作审计等方面落实安全机制。

## 2 任务概述

### 2.1 系统目标

本系统的总体目标是：以共享快递袋为循环载体，建成一套覆盖"取—用—还—洗—调"全流程的在线管理系统，实现快递袋从投放、取用、寄件、回收、消毒到再上架的闭环管控。具体目标分解如下：

| 目标编号 | 目标                                                     | 对应任务书依据 |
| -------- | -------------------------------------------------------- | -------------- |
| G1       | 快递袋全生命周期状态可控、可追溯，杜绝非法跳变与重复领取 | 意义阐述、工作内容⑥ |
| G2       | 库存信息实时透明，并发取袋场景下不超发、不漏发           | 工作内容⑥     |
| G3       | 流转过程全程留痕，损坏与遗失责任可认定                   | 意义阐述       |
| G4       | 站点间调度有数据依据，摆脱经验驱动                       | 意义阐述、工作内容② |
| G5       | 三类角色职责清晰、权限受控，杜绝越权访问                 | 工作内容③④     |
| G6       | 落实网络空间安全专业方向的安全机制（认证、鉴权、脱敏、审计） | 工作内容⑥     |
| G7       | 提供库存预警与周转率/订单趋势等运营决策依据              | 意义阐述、工作内容④ |
| G8       | 系统可部署至云服务器稳定运行，具备可演示、可验收的完整形态 | 工作内容⑦     |

### 2.2 用户特点

系统共设三类角色，其特点与使用场景差异显著，直接决定了界面形态与权限边界：

| 角色         | 人员特征                             | 使用设备与环境                     | 技术水平                     | 核心诉求                                     |
| ------------ | ------------------------------------ | ---------------------------------- | ---------------------------- | -------------------------------------------- |
| 普通用户     | 校园/社区内的寄件人，人数最多、流动性强 | 手机为主（微信内置浏览器或系统浏览器） | 一般，仅需扫码与填表         | 快速取到袋、快速寄件、随时查订单状态         |
| 站点管理员   | 站点值守人员，一人一岗绑定一个站点   | PC 管理界面 + 手机扫码，工作时段使用 | 熟练使用办公软件             | 高效完成入库、回收确认、消毒登记等重复性作业 |
| 平台管理员   | 系统运营管理者，人数最少             | PC 管理界面，长时间在线            | 熟悉后台管理系统             | 全局台账、异常处置、数据统计与调度决策       |

由此推导出的界面形态要求：普通用户端以移动端优先、单列卡片、扫码为主入口；站点管理员端以"扫码即操作"为设计中心，PC 端表格操作与手机端全屏单任务页并存；平台管理员端以数据看板与台账管理为主。

### 3.2 现状与痛点

线下人工登记模式下存在四类突出问题，本系统的功能设计逐条对应解决：

| 编号 | 痛点                             | 现状表现                                             | 本系统的对策                                                 |
| ---- | -------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| P1   | 库存信息不透明                   | 站点余量靠人工清点，用户到站才发现无袋可取而跑空     | 站点库存实时视图（FR-M3-05）、库存预警（FR-M3-06）、并发安全的库存扣减（NFR-PERF-01） |
| P2   | 流转过程不可追溯                 | 一只袋经过谁的手、何时消毒、修过几次，无记录可查     | 全生命周期状态机 + 流转日志（FR-M4-19、FR-M4-06）、消毒/维修/报废独立单据（FR-M4-11、FR-M4-12、FR-M4-14） |
| P3   | 站点间调度依赖经验               | 哪个站点缺、哪个站点富余，全凭感觉，调拨无单据       | 调拨单与在途跟踪（FR-M3-11、FR-M3-12）、库存分布看板（FR-M6-04）     |
| P4   | 损坏与遗失责任难以认定           | 袋丢了找不到责任人，损失由运营方承担                 | 责任认定机制（FR-M5-15）、未归还与超时的自动跟踪（FR-M5-10、FR-M5-13 与 BR-01~BR-07）   |

### 3.3 业务流程分析

**主流程（正常闭环）**：一只快递袋从入库到再上架，经过以下六个环节，构成"取—用—还—洗—调"闭环：

```text
图 3-1 快递袋主业务流程（正常闭环）

  [站点管理员]              [普通用户]                    [站点管理员]
  激活上架                                            回收确认（扫袋码）
      │                       扫码取袋                        │
      ▼                          │                           ▼
  ┌────────┐   扫码申领     ┌────────┐   提交寄件    ┌────────┐
  │  空闲  │ ────────────► │ 已分配 │ ───────────► │ 使用中 │
  └────────┘                └────────┘              └────────┘
      ▲                          │                       │
      │                          │ 未使用回收            │ 标记归还（可选）
      │                          ▼                       ▼
      │                     （回空闲）              ┌──────────┐
      │                                            │ 回收在途 │
      │                                            └──────────┘
      │                                                 │ 回收确认
      │                                                 ▼
      │   上架入库        ┌────────┐   消毒合格     ┌────────┐
      └──────────────────│ 可复用 │ ◄──────────── │ 待消毒 │
                         └────────┘               └────────┘
                              │                        │ 消毒不合格
                              ▼                        ▼
                         （转维修/报废）          ┌────────┐
                                                │ 维修中 │
                                                └────────┘
```

**关键设计取舍（需求侧澄清）**：

1. **回收确认是权威动作，标记归还是可选辅助**。用户点击"标记归还"后袋进入"回收在途"，但只有站点管理员扫码确认才真正完成回收。若用户未标记直接投放，站点管理员扫码同样可以完成回收确认——**不能因为用户没点标记而拒绝回收**。
2. **袋状态是权威事实，订单状态跟随联动**。用户侧看到的"订单状态"由袋状态驱动，不允许单独修改。
3. **实物为锚**：库存回补只发生在实物回归站点并被扫码确认的时点，防止账实分离。

**异常流程**：系统需处理的异常与分支路径详见第 5 章各用例的"备选流"，其业务规则统一登记在第 3.5 节。

### 4.2 用户管理（M1）

**FR-M1-01｜图形验证码获取与校验**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书③；设计书5.1、8.3

- **需求描述**：匿名接口 GET /api/v1/auth/captcha 返回 captchaId 与验证码图片；验证码存 Redis（TTL 3 分钟、一次性使用），注册与锁定后的登录均须校验通过。
- **输入 → 输出**：无（匿名请求） → captchaId、图形验证码图片
- **处理要点**：服务端生成图形验证码并写入 Redis；校验时比对后立即删除，缺失、错误、过期或重复使用的验证码一律校验失败。
- **验收口径**：取码后可成功校验一次；同一验证码重复使用、超过 3 分钟或输入错误均校验失败，注册/登录被拒绝。

**FR-M1-02｜用户注册**　`P0`　角色：普通用户　来源：任务书③；设计书5.1、9.2、10.4

- **需求描述**：手机号 + 密码 + 图形验证码 + 昵称注册，成功后生成普通用户账号；手机号 11 位且唯一，密码 ≥8 位含两类字符，落库仅存 BCrypt 摘要（cost≥10）。
- **输入 → 输出**：手机号、密码、图形验证码、昵称 → 注册结果（成功/失败）
- **处理要点**：先校验图形验证码，再校验手机号格式与唯一性、密码强度；全部通过后写入账号并赋予普通用户角色；任一失败不落库。
- **验收口径**：合法信息注册成功后可用新账号登录；重复手机号、弱密码、验证码错误或过期时注册失败且不产生账号记录。

**FR-M1-03｜用户登录**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书③⑤；设计书5.1、9.2

- **需求描述**：手机号 + 密码登录，校验通过签发 access token（有效期 2 小时）并返回角色，站点管理员附 stationId；登录成功与失败均写入 login_log。
- **输入 → 输出**：手机号、密码 → access token、角色、stationId（站管）
- **处理要点**：按手机号查询账号并 BCrypt 比对密码；通过则签发 JWT；账号不存在、密码错误或账号被禁用均登录失败，不签发 token。
- **验收口径**：正确凭据登录返回 token 与角色并可访问受保护接口；错误凭据或被禁用账号登录失败不发放 token；成功与失败均写登录日志。

**FR-M1-04｜JWT 签发与校验**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书⑥；设计书7.1、4.2

- **需求描述**：登录/续签签发的 access token 有效期 2 小时、HS256 签名；载荷含 uid/role/stationId（站管）/tokenVersion/jti/exp；密钥 ≥32 字节经环境变量注入。
- **输入 → 输出**：认证通过的登录/续签请求 → JWT 字符串、校验结果
- **处理要点**：签发时写入当前 token_version 与唯一 jti；请求由过滤器校验签名、有效期、jti 黑名单与 token_version，固定 HS256、拒绝其他算法。
- **验收口径**：解码 token 可见 uid 与角色（站管含 stationId）；过期、签名篡改或 alg 非 HS256 的 token 请求返回 401/1001。

**FR-M1-05｜登录失败锁定与限流**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书⑥；设计书5.1、9.2、9.6

- **需求描述**：同一账号连续登录失败 5 次锁定 15 分钟（Redis 计数）；锁定期间登录返回 1002，锁定后登录须校验图形验证码；登录接口限流超频返回 5101。
- **输入 → 输出**：账号、失败次数、请求频次 → 锁定状态、错误码 1002/5101
- **处理要点**：失败计数 +1，达 5 次置 15 分钟锁；锁定期内即使密码正确亦拒绝；成功登录清零计数；固定窗口限流控制请求频次。
- **验收口径**：连续 5 次失败后 15 分钟内登录（含正确密码）返回 1002；15 分钟后恢复可登录；超过限流阈值的请求返回 5101。

**FR-M1-06｜静默续签**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书③⑥；设计书5.1、7.1、10.3

- **需求描述**：登录用户剩余有效期 <30 分钟时可调 POST /api/v1/auth/refresh 续签：旧 jti 列入黑名单，签发有效期重新计算的新 token。
- **输入 → 输出**：当前有效 token（剩余 <30min） → 新 access token
- **处理要点**：校验 token 有效且未被吊销后签发新 token；旧 jti 写入 auth:deny:{jti}（TTL=旧 token 剩余有效期）；其他登录端不受影响。
- **验收口径**：续签返回新 token 且有效期重置为 2 小时；旧 token 再次请求返回 401/1001；同账号其他端 token 仍可正常使用。

**FR-M1-07｜退出登录（jti 黑名单）**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书③⑥；设计书5.1、7.1

- **需求描述**：POST /api/v1/auth/logout 将当前 token 的 jti 写入 Redis 黑名单（auth:deny:{jti}，TTL=token 剩余有效期），仅失效当前端，支持多端同时在线。
- **输入 → 输出**：当前 access token → 登出结果
- **处理要点**：登出提取 jti 写入黑名单；此后该 token 的任何请求被拦截器比对拒绝，返回 401/1001；全量失效由 token_version 承担。
- **验收口径**：登出后原 token 请求返回 401/1001；同账号其他端 token 仍可正常访问；黑名单键随 token 到期自动清除。

**FR-M1-08｜个人信息查询（脱敏）**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书④⑥；设计书5.1、8.2、9.5

- **需求描述**：GET /api/v1/users/me 返回本人昵称、角色与站点绑定（站管）；手机号出参一律脱敏为 138****1234，响应不含密码摘要等敏感字段。
- **输入 → 输出**：本人 access token → 昵称、脱敏手机号、角色、stationId
- **处理要点**：uid 取自 token 而非前端参数；查询本人记录并按脱敏规则组装出参；未认证请求由拦截器直接拒绝。
- **验收口径**：登录后查询返回本人信息且手机号形如 138****1234；响应不含密码字段；未认证请求返回 401/1001。

**FR-M1-09｜个人信息修改**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书④；设计书5.1、10.4

- **需求描述**：PATCH /api/v1/users/me 修改昵称等非敏感字段；手机号、角色、状态、站点绑定等敏感字段不开放自助修改，携带提交也不生效。
- **输入 → 输出**：昵称等非敏感字段 → 修改结果
- **处理要点**：仅白名单字段参与更新；字段格式或长度非法返回 3001；请求中携带的敏感字段被忽略，库中值保持不变。
- **验收口径**：修改昵称后重新查询返回新昵称；尝试提交修改手机号后查询，手机号保持不变。

**FR-M1-10｜修改密码（全量吊销）**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书③⑥；设计书5.1、7.1、9.2

- **需求描述**：POST /api/v1/users/me/password 校验旧密码后修改密码，新密码须 ≥8 位含两类字符；修改成功触发 token_version+1，本人全部会话立即失效。
- **输入 → 输出**：旧密码、新密码 → 修改结果
- **处理要点**：BCrypt 比对旧密码，不符即拒绝；新密码按策略校验后重算摘要落库；token_version 自增并删除 auth:userver 缓存。
- **验收口径**：旧密码错误时修改被拒绝；成功后旧密码无法登录、新密码可登录，改密前签发的 token 请求返回 401/1001。

**FR-M1-11｜首登强制改密**　`P1`　角色：平台管理员　来源：设计书4.2

- **需求描述**：初始化 SQL 预置一名平台管理员；该账号首次以初始密码登录后，系统强制其修改密码，未完成改密前不得进行业务操作。
- **输入 → 输出**：预置管理员账号与初始密码 → 强制改密引导、改密完成状态
- **处理要点**：首次登录命中强制改密规则，引导进入改密流程；改密按密码策略校验通过后解除限制、放行全部功能。
- **验收口径**：预置管理员首次登录后被强制改密，改密完成前业务功能不可用；完成改密后功能恢复正常。

**FR-M1-12｜创建账号并授予角色**　`P0`　角色：平台管理员　来源：任务书③④；设计书5.1、4.2、4.3

- **需求描述**：平台管理员通过 POST /api/v1/users 创建账号并授予角色（普通用户/站点管理员/平台管理员）；站点管理员必须同时绑定站点；手机号唯一、密码满足策略。
- **输入 → 输出**：手机号、初始密码、昵称、角色、站点（站管） → 新账号与角色绑定结果
- **处理要点**：仅平台管理员可调用（其他角色 403/2001）；校验手机号唯一与角色合法；站管缺站点则拒绝创建；写操作携带 clientRequestId 幂等。
- **验收口径**：新账号可凭初始密码登录且具对应角色；重复手机号或站管缺站点时创建被拒；非平台管理员调用返回 403/2001。

**FR-M1-13｜站点绑定与换绑**　`P0`　角色：平台管理员　来源：任务书③；设计书4.2、5.1

- **需求描述**：PUT /api/v1/users/{id}/station 为站点管理员绑定/换绑站点：该操作是 JWT stationId 声明的唯一来源；换绑触发 token_version+1，旧 token 立即失效。
- **输入 → 输出**：用户 id、站点 id → 绑定结果、新 token 的 stationId
- **处理要点**：仅平台管理员可调用；校验用户与站点存在、站点管理员必须持有站点；更新后自增 token_version 并清 auth:userver 缓存。
- **验收口径**：绑定后该站管重新登录所得 token 携带 stationId；换绑后旧 token 请求返回 401/1001，新 token 携带新站点。

**FR-M1-14｜用户角色调整**　`P1`　角色：平台管理员　来源：任务书③；设计书5.1、4.2、7.1

- **需求描述**：PUT /api/v1/users/{id}/roles 调整用户角色；角色变更触发 token_version+1，旧 token 立即失效，新权限自重新登录签发的 token 生效。
- **输入 → 输出**：用户 id、目标角色 → 角色调整结果
- **处理要点**：仅平台管理员可调用；校验目标角色属于三类固定角色；更新 sys_user_role 后自增 token_version，操作记入审计日志。
- **验收口径**：角色变更后旧 token 请求返回 401/1001；用户重新登录后按新角色获得对应接口权限，旧角色权限失效。

**FR-M1-15｜用户分页查询**　`P1`　角色：平台管理员　来源：任务书③④；设计书5.1、6.1、9.5

- **需求描述**：GET /api/v1/users 供平台管理员分页查询用户，支持按手机号、角色、状态筛选；列表手机号脱敏输出，不返回密码摘要。
- **输入 → 输出**：分页参数、手机号/角色/状态筛选条件 → 用户分页列表（records/total/pages）
- **处理要点**：仅平台管理员可调用；按条件分页检索（pageNum/pageSize，pageSize 最大 100）；出参统一脱敏并裁剪敏感字段。
- **验收口径**：按手机号、角色、状态筛选结果正确、分页总数一致；返回项手机号均为掩码且不含密码字段。

**FR-M1-16｜用户启停（封禁即失效）**　`P1`　角色：平台管理员　来源：任务书③⑥；设计书5.1、7.1、7.3

- **需求描述**：PATCH /api/v1/users/{id}/status 启用或禁用账号；禁用触发 token_version+1，存量 token 下一次请求即被拒绝，WebSocket 通道在 ≤30s 心跳内断开。
- **输入 → 输出**：用户 id、目标状态（启用/禁用） → 账号状态变更结果
- **处理要点**：仅平台管理员可调用；禁用自增 token_version 并清缓存；被禁用账号无法登录；重新启用后恢复登录能力。
- **验收口径**：禁用后该用户存量 token 请求返回 401/1001 且无法登录；启用后可正常登录；非平台管理员调用返回 403/2001。

**FR-M1-17｜重置用户密码**　`P1`　角色：平台管理员　来源：任务书③④；设计书5.1、7.1

- **需求描述**：POST /api/v1/users/{id}/password-reset：平台管理员为指定用户重置密码，新密码满足 ≥8 位含两类字符；重置触发 token_version+1，吊销该用户全部会话。
- **输入 → 输出**：用户 id、新密码 → 重置结果
- **处理要点**：仅平台管理员可调用；按密码策略校验新密码并重算 BCrypt 摘要；自增 token_version 并清 auth:userver 缓存。
- **验收口径**：重置后该用户旧密码登录失败、新密码登录成功；其存量 token 请求返回 401/1001；非平台管理员调用返回 403/2001。

**FR-M1-18｜前端登录态与 401 处理**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书④⑤；设计书6.3、10.3

- **需求描述**：前端以 Pinia 保存 token/role/stationId，token 内存为主、sessionStorage 兜底；请求自动携带 Authorization；401 清除 token 跳登录并保留回跳路由。
- **输入 → 输出**：登录结果、接口 401/403 响应 → 登录态、页面跳转与回跳
- **处理要点**：路由守卫拦截未登录访问并跳转登录页；请求拦截器注入 token；401 清 token 跳登录，403 提示无权限。
- **验收口径**：未登录访问受保护页面被重定向到登录页；接口返回 401 后本地 token 被清除，重新登录后回跳原路由。

### 4.3 共享快递袋服务（M2）

**FR-M2-01｜扫码查询袋信息**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容①、⑥；设计书3.4.1、5.2、7.4

**FR-M2-02｜扫码申领取袋**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容③、⑥；设计书3.2#2、3.4.1、5.2、7.2

- **需求描述**：用户扫码申领空闲快递袋：校验袋状态与调拨锁定后，原子扣减站点库存并生成待寄件订单、袋转已分配；库存不足、状态非法、并发重复领取返回对应错误码。
- **输入 → 输出**：袋码、clientRequestId幂等头 → 订单号、待寄件订单
- **处理要点**：状态机转移#2：Lua原子完成限额校验、库存DECR、写25h预扣凭据，随后DB事务建订单并条件UPDATE袋（空闲+版本一致）；DB失败按R0同步补偿。
- **验收口径**：并发申领同一袋仅1单成功（4103）；库存不足4101；非空闲或被调拨锁定袋被拒；失败无订单且库存不泄漏。

**FR-M2-03｜申领限额与频次控制**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容①、⑥；设计书3.5、5.2、7.2

- **需求描述**：同一用户未归还订单（待寄件/使用中/待回收确认）不得超过3单，每日申领不超过10次；订单进入三态计数+1、离开−1；超限分别返回4104、4109。
- **输入 → 输出**：用户ID、申领事件（含当日日期） → 放行或4104/4109错误
- **处理要点**：取袋Lua内比较 borrow:open（<3）与 borrow:daily（<10）后原子INCR；open计数14天滑动，daily当日有效；撤回/取消也计入日频次。
- **验收口径**：第4笔未归还订单申领返回4104；当日第11次申领返回4109；已完成/已取消订单不占未归还额度。

**FR-M2-04｜申领幂等与防重复领取**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容⑥；设计书3.3、6.1、7.2、9.6

- **需求描述**：写操作以 clientRequestId 幂等：重复提交返回首次结果，不重复扣库存、不重复建单；同一只袋被并发申领时由DB条件更新兜底，仅一笔成功，其余返回4103。
- **输入 → 输出**：clientRequestId（客户端UUID）、袋码 → 首次结果或4103错误
- **处理要点**：Redis幂等键（TTL10min）命中即返回首次结果；袋条件UPDATE影响行数为0即并发冲突，按R0补偿并报4103。
- **验收口径**：同clientRequestId重复申领仅1单、库存只扣1；两请求并发申领同一袋仅1单成功（4103）；补偿后库存与计数复原。

**FR-M2-05｜登记寄件信息**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容③、④、⑥；设计书3.2#3、3.4.1、5.2

- **需求描述**：取袋后登记快递公司与运单号：校验格式合法且公司+运单号联合唯一，通过后订单与袋同步转使用中并删除预扣凭据；收件人手机号仅存脱敏掩码与哈希。
- **输入 → 输出**：订单号、快递公司、运单号、收件人手机号 → 使用中的订单与袋
- **处理要点**：校验订单为待寄件（否则4105）→参数格式与运单联合唯一校验→事务执行转移#3→删除预扣凭据→推送库存与订单主题。
- **验收口径**：重复公司+运单号被拒且订单仍待寄件；对已取消订单提交寄件返回4105；成功后袋与订单同步为使用中。

**FR-M2-06｜标记已投放回收箱**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容③、④；设计书3.2#6、3.4.2、5.2

**FR-M2-07｜撤回申领**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容③；设计书3.2表后说明、3.5、3.6、5.4、7.2

**FR-M2-08｜我的订单查询**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容④；设计书3.6、4.4、5.2、6.1

**FR-M2-09｜超时未归还提醒**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容⑥；设计书3.5、3.6、5.5、7.5

**FR-M2-10｜附近站点查询**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容④；设计书5.2、5.3、7.2

- **处理要点**：事务提交后向库存与订单主题推送（站点、袋码、新状态、库存数）；事务回滚不推送；前端断线重连后拉取最新状态。

- **处理要点**：接口权限“登录用户”含管理角色；数据范围仍限本人订单，不因角色扩大；限额规则对所有角色一致适用。

**FR-M2-13｜Redis故障降级申领**　`P1`　角色：普通用户、站点管理员、平台管理员　来源：任务书工作内容⑥；设计书7.2降级路径

- **处理要点**：角色与站点范围校验→Redis优先读取可用库存→按DB汇总其余状态计数→返回实时库存视图。
- **验收口径**：可用库存等于该站空闲袋数、各状态计数与DB一致；越权查询报2002；计数未就绪返回5102可重试。

**FR-M3-06｜库存预警与阈值**　`P0`　角色：站点管理员、平台管理员　来源：任务书②⑥；设计书5.3、5.6、7.3

- **需求描述**：站点配置预警阈值warn_threshold；可用库存低于阈值的站点进入预警列表，平台管理员可查询，作为站点间调拨的调度决策依据。

- **验收口径**：可用库存低于阈值时站点进入预警列表、看板预警站点数加1；补货至阈值及以上后预警解除。

**FR-M3-07｜回收箱待确认清单**　`P1`　角色：站点管理员、平台管理员　来源：任务书③；设计书5.3、3.4.2、7.3

- **需求描述**：站点管理员查看本站回收箱待确认清单：含已标记投放本站（回收在途）的袋与未标记但状态为使用中的袋，供清点后逐只扫码确认。
- **输入 → 输出**：站点ID、筛选条件 → 待确认袋清单
- **处理要点**：站点范围校验→查询回收在途（return_station_id=本站）及未标记使用中袋→输出袋码、状态与标记情况。
- **验收口径**：标记归还至本站的袋必在清单；未标记但使用中的袋可见；非本站管理员查询报2002。

**FR-M3-08｜扫码回收确认**　`P0`　角色：站点管理员、平台管理员　来源：任务书③⑥；设计书3.2（#4/#5/#7/#8路由）、3.4.2、5.3

- **需求描述**：站点管理员扫码（或手输袋码）逐只回收确认，后端按绑定订单状态自动路由：订单已取消/不存在→#4袋回空闲，待寄件→#5，使用中→#7，待回收确认→#8；#5/#7/#8袋转待消毒并归属确认站点。
- **输入 → 输出**：站点ID、袋码（扫码或手输） → 逐袋确认结果
- **处理要点**：袋码校验→按订单状态路由（已取消/不存在#4、待寄件#5、使用中#7、待回收确认#8）→事务内更新袋态、订单、计数、use_count并推送。
- **验收口径**：#4已取消/不存在→袋回空闲、库存+1、不入消毒；#5转已取消；#7/#8转已完成、use_count+1；#5/#7/#8计数−1、袋待消毒、归属改确认站点。

**FR-M3-09｜回收确认异常处理**　`P1`　角色：站点管理员、平台管理员　来源：设计书3.2、6.1、6.4、9.6

- **需求描述**：回收确认的异常与边界：袋码不存在、状态非法、重复确认按错误码拒绝；批量扫码逐袋执行、逐袋幂等，单只失败不影响其余。
- **输入 → 输出**：袋码列表（扫码逐只提交） → 逐袋成功/失败明细
- **处理要点**：逐袋校验袋码（4106）与状态（4102/4107）→非法项单独失败并记录→合法项照常转移→返回逐袋结果；幂等键含袋码。
- **验收口径**：空闲、待消毒或已确认袋再次确认被拒（4102/4107）；批量扫码单只失败其余成功且返回逐袋结果明细。

**FR-M3-10｜跨站归还与未标记直投**　`P0`　角色：站点管理员、平台管理员　来源：任务书⑥；设计书3.4.2、4.4、9.3

- **需求描述**：支持用户将快递袋投放任意站点（含未标记直接投放）：回收确认的站点校验对象为回收箱所属站点（操作人站点），确认前不校验袋旧归属。
- **输入 → 输出**：站点ID、袋码 → 确认结果与新归属站点
- **处理要点**：扫码→以操作人站点作为回收箱站点校验权限→状态机按订单状态路由→确认事务中将station_id改为确认站点并写审计。
- **验收口径**：袋归属非本站、用户未标记时，本站扫码确认仍成功；确认后袋归属改为本站且产生审计记录。

**FR-M3-11｜调拨单创建与锁定**　`P0`　角色：平台管理员　来源：任务书③；设计书3.4.3、5.3、7.2

- **需求描述**：平台管理员创建调拨单（源站→目标站、袋码明细）：明细须为源站空闲袋；建单即锁定明细袋，锁定期间该袋不能被申领。
- **输入 → 输出**：源站、目标站、袋码清单 → 调拨单号（待出库）
- **处理要点**：校验源/目标站点与袋码（存在、空闲、属源站、未被未出库调拨单引用）→建单（待出库）→写明细并加锁。
- **验收口径**：建单成功后明细袋申领报冲突；含不存在、非空闲或非源站袋码的清单被拒并指明袋码。

**FR-M3-12｜调拨单跟踪与超时提示**　`P1`　角色：平台管理员　来源：设计书3.4.3、5.3、7.5；注：调拨单列表/明细查询、核收进度与在途超时提示的对应接口需补入设计书5.3（需求先于设计）

- **输入 → 输出**：状态、时间筛选条件 → 调拨单列表与明细进度
- **处理要点**：权限校验→按状态与时间筛选单据→汇总明细已出库、已核收数量→对超时在途单标注提示。
- **验收口径**：首只出库后单据为在途、全部核收为已完成、部分核收或遗失为异常；出库满48小时未核收的在途单被标注提示。

**FR-M3-13｜调拨出库**　`P0`　角色：站点管理员、平台管理员　来源：设计书3.2（#16）、5.3、4.4

- **需求描述**：源站（或平台）管理员对调拨单逐只扫码出库：袋由空闲转调拨在途，源站可用库存减1；首只出库后单据状态转为在途。
- **输入 → 输出**：调拨单ID、袋码 → 出库结果与单据状态
- **处理要点**：校验操作人为源站管理员→扫码校验袋码在明细中→执行#16并扣减源站库存→首只出库置单据在途→推送。
- **验收口径**：出库后袋为调拨在途、源站可用库存减1、明细写核验记录；非源站管理员操作报2002。

**FR-M3-14｜调拨核收入库**　`P0`　角色：站点管理员、平台管理员　来源：设计书3.2（#17）、5.3、4.4

- **需求描述**：目标站（或平台）管理员扫码核收：袋由调拨在途转空闲，归属改为目标站，目标站可用库存加1；全部明细核收后单据转已完成。
- **输入 → 输出**：调拨单ID、袋码 → 核收结果与单据状态
- **处理要点**：校验操作人为目标站管理员→扫码校验袋码与明细一致→执行#17、改归属、加库存→全部核收后闭环推送。
- **验收口径**：核收后袋归属为目标站、该站可用库存加1、明细标记核收；非目标站操作报2002；全收后单据已完成。

**FR-M3-15｜调拨取消与明细剔除**　`P1`　角色：平台管理员　来源：设计书3.4.3、5.3、6.4

- **需求描述**：调拨单取消：仅待出库可整单取消，明细袋解锁回空闲；出库扫码失败（实物缺失/码损）时平台管理员可剔除未出库明细，袋回空闲后其余继续。
- **输入 → 输出**：调拨单ID、明细袋码 → 取消/剔除结果
- **处理要点**：校验单据状态（非待出库报4105）→取消或剔除明细→解锁回空闲→记录操作与原因。
- **验收口径**：非待出库单据取消报4105；剔除仅限待出库/在途且该袋未出库；解锁后袋可再次被申领。

**FR-M3-16｜在途遗失确认**　`P1`　角色：平台管理员　来源：设计书3.2（#19、责任认定）、3.5

- **需求描述**：平台管理员对出库后≥48小时未核收的调拨执行在途遗失确认：袋转已遗失，调拨单转异常，写责任记录（责任主体为源站、由平台管理员裁决）。
- **输入 → 输出**：调拨单ID、责任与处置结论 → 遗失确认结果
- **处理要点**：校验单据在途且满足超时条件→执行#19→单据置异常→登记责任主体与处置结论→留痕。
- **验收口径**：仅出库满48小时未核收的单可确认；确认后袋为已遗失、单据为异常、责任记录主体为源站；未达时限被拒。

**FR-M3-17｜回收在途超时提醒**　`P1`　角色：站点管理员、平台管理员　来源：设计书3.5、7.5

- **需求描述**：系统扫描回收在途袋：标记归还后24小时未确认向本站推送提醒；72小时未确认纳入平台异常清单，平台管理员可发起确认遗失流程。
- **输入 → 输出**：回收在途袋数据 → 站点提醒、异常清单
- **处理要点**：定时任务每15分钟扫描回收在途→满24小时触发站点提醒推送→满72小时纳入异常清单→支持发起遗失确认。
- **验收口径**：标记归还满24小时未确认触发本站提醒；满72小时未确认出现在平台异常清单并可发起遗失确认。

**FR-M3-18｜库存实时推送**　`P1`　角色：站点管理员、平台管理员　来源：任务书⑥；设计书7.3

- **需求描述**：基于WebSocket向本站管理员与平台管理员推送可用库存增减（station/{id}/stock）与用户标记归还提醒（station/{id}/recycle）。
- **输入 → 输出**：库存变化、标记归还等业务事件 → WebSocket推送消息
- **处理要点**：连接后首帧JWT鉴权→按令牌声明生成订阅白名单→业务事务提交后推送→心跳复查token有效性。
- **验收口径**：申领、上架入库、调拨入库/出库等库存变化实时推送至该站主题；标记归还推送站主题；越权订阅被拒。

**FR-M3-19｜站点库存对账**　`P1`　角色：平台管理员　来源：设计书7.2（R4）、7.5、6.4

- **需求描述**：每30分钟逐站点对账：以数据库空闲袋数为权威修正Redis计数，差异写入告警；对账窗口内相关请求可重试，防止计数漂移影响库存视图。
- **输入 → 输出**：站点库存计数（Redis与DB） → 修正后的计数与差异告警
- **处理要点**：SETNX对账标记（TTL120秒）→间隔1秒两次读DB空闲袋数一致→写回Redis→记差异告警→释放标记。
- **验收口径**：人为制造计数偏差后一轮对账内被修正为DB口径并产生告警；对账期间请求获得可重试响应而非错误扣减。

**FR-M3-20｜站点数据权限校验**　`P0`　角色：站点管理员、平台管理员　来源：任务书⑥；设计书4.3、4.4、9.3

- **需求描述**：M3接口按事件上下文执行数据范围校验：库存查询与回收确认比对操作人站点，调拨出库比对源站、核收比对目标站；越权返回2002并记审计。
- **输入 → 输出**：请求令牌、目标资源标识 → 放行结果或2002拒绝
- **处理要点**：统一拦截器做角色校验（2001）→Service层归属二次校验→按ID取详情后比对归属兜底。
- **验收口径**：站点管理员查询或操作非本站资源、非源站出库、非目标站核收均报2002；平台管理员全站放行并标记代操作。

**FR-M3-21｜关键操作审计留痕**　`P1`　角色：平台管理员　来源：任务书⑥；设计书7.6、9.1

- **需求描述**：站点新增/编辑/停用、调拨各节点与回收确认（含跨站与未标记直投）等关键操作强制留痕：操作人、角色、IP、结果与耗时，审计记录只增不改。
- **输入 → 输出**：操作上下文（操作人、动作、参数、结果） → 审计日志记录
- **处理要点**：审计注解AOP采集→敏感字段脱敏→写审计表（只插不改）→越权与状态机拒绝事件同步入审计。
- **验收口径**：执行上述任一操作后可按操作人/时间查得含结果与错误码的审计记录，记录不可修改或删除。

### 4.5 快递袋管理（M4）

**FR-M4-01｜新建快递袋档案**　`P0`　角色：平台管理员　来源：设计书5.4/7.4；任务书工作内容③

- **需求描述**：平台管理员录入规格、颜色、容量与登记站点，系统自动生成唯一袋码，新袋初始状态为未激活，未激活期间即写入登记站点归属。
- **输入 → 输出**：规格、颜色、容量、登记站点 → 袋档案记录（袋码+未激活状态）
- **处理要点**：校验必填与格式（3001）；按编码规则生成袋码；编码唯一约束防重；初始状态置未激活。
- **验收口径**：创建后袋码符合编码格式且校验位正确、状态为未激活、station_id=所选登记站点；编码重复时创建失败且不产生两条记录。

**FR-M4-02｜袋码生成与校验规则**　`P0`　角色：平台管理员　来源：设计书7.4/10.4/9.4

- **需求描述**：袋码格式为 SJB-{规格码1位}-{出厂年月yyMM}-{5位流水}-{1位校验码}，流水连续、末位校验码采用模31混淆算法，编码不承载站点语义。
- **输入 → 输出**：规格码、出厂年月、流水号 → 合法袋码或校验失败提示
- **处理要点**：按规格分配连续流水；计算模31校验位；手输或扫码先验格式与校验位，再查存在性（4106）。
- **验收口径**：生成的袋码均通过格式与校验位校验；篡改任一位后被拒（3001/4106）；同规格流水号连续不跳号。

**FR-M4-03｜批量生成袋档案与二维码**　`P0`　角色：平台管理员　来源：设计书5.4/7.4；任务书工作内容③④

- **需求描述**：平台管理员按登记站点批量生成袋档案（≤500只/批），后端用 ZXing 生成含编码文本的二维码 PNG 并打包 ZIP 供下载打印；整批原子提交。
- **输入 → 输出**：数量、规格/颜色/容量、登记站点 → 批量袋档案与二维码 ZIP
- **处理要点**：数量超500拒绝（3001）；同事务写入整批档案并生成二维码；打包 ZIP 为统一 JSON 响应的声明式例外。
- **验收口径**：生成500只得500个未激活档案且袋码唯一；超500报3001；整批任一只失败时全部不落库；ZIP 内 PNG 数量等于成功生成数。

**FR-M4-04｜二维码内容与展示**　`P0`　角色：平台管理员、站点管理员　来源：设计书7.4/10.3；任务书工作内容④

- **需求描述**：二维码内容为 https://{域名}/m/bag/{袋码}，域名由配置注入、不做签名；袋台账与袋详情页展示二维码与编码文本，用于打印贴标与人工核对。
- **输入 → 输出**：袋码、域名配置 → 可扫描二维码与袋码文本
- **处理要点**：按配置域名拼装 URL 生成二维码；管理端展示二维码与可读编码文本；域名变更需换标重印或旧域名301跳转。
- **验收口径**：扫描二维码解析出的 URL 中袋码与档案一致；袋台账与详情可查看二维码及编码文本；打印贴标前该袋保持未激活状态。

**FR-M4-05｜袋台账查询与数据范围**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/4.4

- **需求描述**：站点管理员与平台管理员分页查询袋台账，支持按状态、站点、编码筛选；本站站点管理员仅可见本站袋，平台管理员可见全站。
- **输入 → 输出**：状态、站点、编码关键字、分页参数 → 袋台账分页列表
- **处理要点**：按角色注入数据范围过滤（站点管理员限本站）；组合筛选分页；命中他站资源按越权拦截（2002）。
- **验收口径**：站点管理员查询结果不出现他站袋，显式请求他站数据被拒（2002）；平台管理员可查全站；状态/编码筛选结果与条件一致。

**FR-M4-06｜袋全生命周期流转追溯**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2；任务书工作内容⑥

- **需求描述**：按袋码查询全生命周期流转日志（前态、后态、事件、操作人、站点、时间）支撑流转过程可追溯；本站站点管理员仅可查本站袋，袋码不存在报4106。
- **输入 → 输出**：袋码 → 流转日志时间线
- **处理要点**：校验袋存在性（4106）与数据范围（本站/全站）；按时间序列返回 bag_transfer_log 记录。
- **验收口径**：完成激活→申领→回收→消毒→上架后，追溯结果按时间列出全部转移且前后态衔接正确；他站管理员查询报2002；不存在袋码报4106。

**FR-M4-07｜激活上架（未激活转空闲）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#1)/5.3；任务书工作内容④

- **需求描述**：站点管理员对本站登记的新袋执行激活上架，袋由未激活转为空闲进入可申领循环；按袋的登记站点校验归属，平台管理员可全站代操作。
- **输入 → 输出**：袋码（扫码或手输） → 状态=空闲、入库记录、库存+1
- **处理要点**：状态机校验转移#1；校验操作人站点=登记站点且站点未停用；写入库记录；库存+1；提交后推送。
- **验收口径**：登记站点管理员激活成功后状态=空闲、生成入库记录、库存计数+1；重复激活报4102；非登记站点操作报2002；停用站点的袋不可激活。

**FR-M4-08｜上架入库（可复用转空闲）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#11)/3.5

- **需求描述**：消毒合格的可复用袋由站点管理员上架入库回到空闲；复用次数达到上限的袋拒绝上架，提示转维修或报废。
- **输入 → 输出**：袋码 → 状态=空闲、入库记录、库存+1
- **处理要点**：状态机校验转移#11；前置校验 use_count<max_use_count（默认50，可配置），超限报4108；写入库记录；库存+1。
- **验收口径**：use_count未超限时可复用袋上架成功且库存+1；use_count≥上限报4108、状态不变并提示转维修/报废；非可复用状态上架报4102。

**FR-M4-09｜未使用回收（已分配转空闲）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#4)

- **需求描述**：用户撤回或24h超时取消订单后袋未离站的，站点管理员扫码执行未使用回收，袋回到空闲；前置为绑定订单已取消或不存在。
- **输入 → 输出**：袋码 → 状态=空闲、订单闭环、库存+1
- **处理要点**：状态机校验转移#4；校验绑定订单已取消/不存在；订单闭环；库存+1；写入库记录。
- **验收口径**：已取消订单的已分配袋回收成功（状态=空闲、库存+1）；订单仍为待寄件时接口拒绝且袋状态不变；非本站袋操作报2002。

**FR-M4-10｜出库登记（报废与差异出库）**　`P1`　角色：站点管理员、平台管理员　来源：设计书5.4

- **需求描述**：站点管理员登记出库，仅用于报废袋实物出库与经批准的盘点差异出库，写 stock_record 出库记录；维修流程不走出库接口。
- **输入 → 输出**：袋码、出库原因、盘点单号 → 出库记录
- **处理要点**：校验场景白名单（报废袋/已批准盘点差异）；维修中袋拒绝并提示走维修接口；写OUT/SCRAP_OUT出库记录。
- **验收口径**：对报废袋出库成功并生成出库记录；对维修中或正常在用袋调用出库被拒；无盘点单号的盘点差异出库被拒。

**FR-M4-11｜消毒批次登记（合格/不合格）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#9#10)；任务书工作内容③④

- **需求描述**：站点管理员按批次登记消毒，明细袋码≤200只/批并逐袋判定：合格转可复用，不合格转维修中并登记缺陷说明；批次与明细留档。
- **输入 → 输出**：消毒方式/时间、袋码明细与逐袋结果 → 消毒批次与逐袋处理结果
- **处理要点**：批次号唯一；逐只执行转移#9（合格→可复用）/#10（不合格→维修中）；单只失败不影响其余；逐袋返回结果明细。
- **验收口径**：一批200只逐袋返回处理结果；合格袋转可复用、不合格袋转维修中且必须有缺陷说明（缺失报3001）；batch_no重复报错；单只失败不影响其余袋。

**FR-M4-12｜维修登记（转维修中）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#12)；任务书工作内容③

- **需求描述**：空闲、待消毒或可复用的袋发现破损时，站点管理员登记破损描述后转维修中；前态为空闲时同步扣减站点可用库存。
- **输入 → 输出**：袋码、破损描述 → 状态=维修中、维修记录
- **处理要点**：状态机校验转移#12；破损描述必填（3001）；前态=空闲时库存−1；写维修登记记录。
- **验收口径**：空闲/待消毒/可复用袋均可转维修中并生成维修记录；破损描述缺失报3001；前态=空闲时库存−1；使用中袋登记维修报4102。

**FR-M4-13｜维修完成（修复或报废）**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#13#14)

- **需求描述**：维修完成后登记结果：修复转可复用；无法修复或复用次数已超限转报废，同时写维修完成记录与报废记录。
- **输入 → 输出**：袋码、维修结果、说明 → 状态=可复用或报废
- **处理要点**：状态机校验转移#13/#14；修复→可复用；无法修复或 use_count≥上限→报废；报废分支写报废记录。
- **验收口径**：结果=修复时状态=可复用；结果=无法修复时状态=报废并生成报废记录；对非维修中袋调用报4102。

**FR-M4-14｜直接报废登记**　`P0`　角色：站点管理员、平台管理员　来源：设计书5.4/3.2(#15)/7.6

- **需求描述**：空闲、待消毒或可复用的袋因严重破损、超限等原因由站点管理员直接报废，写报废记录；报废为终态，报废操作属审计重点核查项。
- **输入 → 输出**：袋码、报废原因 → 状态=报废、报废记录
- **处理要点**：状态机校验转移#15；报废原因必填；前态=空闲时库存−1；写报废记录；报废事件写审计日志。
- **验收口径**：三种前态均可报废并写报废记录；报废后该袋任何转移请求均报4102；前态=空闲时库存−1；报废动作可在审计日志查到。

**FR-M4-15｜遗失找回（已遗失转待消毒）**　`P1`　角色：平台管理员　来源：设计书5.4/3.2(#20)

- **需求描述**：确认遗失的袋被找回后由平台管理员登记找回说明与找回站点，袋转待消毒回流循环；责任记录追加已找回注记，不重复计复用次数。
- **输入 → 输出**：袋码、找回说明、找回站点 → 状态=待消毒、责任记录更新
- **处理要点**：状态机校验转移#20；station_id改为找回登记站点；责任记录追加注记；use_count保持不变；后续按正常消毒流程。
- **验收口径**：找回后状态=待消毒、station_id=找回站点、use_count不变；对非已遗失袋调用报4102；站点管理员调用报2001（仅平台管理员可操作）。

**FR-M4-16｜状态修正（白名单目标态）**　`P1`　角色：平台管理员　来源：设计书5.4/3.2(#21)/3.4.4

- **需求描述**：盘点差异等场景下平台管理员可对非终态袋人工修正状态，必须填写盘点差异单号与修正原因，目标态限白名单：空闲、维修中、已遗失、报废。
- **输入 → 输出**：袋码、目标状态、盘点差异单号、修正原因 → 修正后状态与库存增减
- **处理要点**：状态机校验转移#21；白名单外目标态拒绝；按源/目标态增减库存；跨站修正同步station_id；报废/遗失写对应记录并联动订单；审计留痕。
- **验收口径**：白名单外目标态被拒且袋状态不变；缺盘点单号或修正原因报3001；源=空闲且目标≠空闲库存−1、目标=空闲库存+1；修正事件入审计且事件=人工修正。

**FR-M4-17｜库存盘点单提交**　`P1`　角色：站点管理员、平台管理员　来源：设计书5.4/3.4.4

- **需求描述**：站点管理员发起盘点：系统展示本站各状态账面数，录入实际数后生成盘点单并自动计算差异与袋级差异清单；盘点单不可删除，仅可作废重盘。
- **输入 → 输出**：站点、各状态实际数、袋级差异明细 → 盘点单（账面/实际/差异+差异袋清单）
- **处理要点**：账面数按DB中各状态袋数实时统计（DB为权威口径）；差异=实际−账面；写入diff_bags_json差异袋清单；作废后可重盘。
- **验收口径**：提交后生成含各状态账面/实际/差异数与袋级差异清单的盘点单；差异清单含袋码与差异类型；盘点单无删除途径，作废后可重新盘点。

**FR-M4-18｜出入库库存计数联动与对账**　`P0`　角色：站点管理员、平台管理员　来源：设计书7.2/7.5/3.1

- **需求描述**：激活上架、上架入库、未使用回收成功后站点可用库存+1，空闲袋转维修或报废等离架操作库存−1；计数以DB空闲袋数为权威，每30分钟对账纠偏。
- **输入 → 输出**：转移事件、站点 → Redis可用库存计数
- **处理要点**：转移事务内同步Redis计数增减；对账任务每30分钟以COUNT(IDLE)校准并互斥；Redis故障时降级DB路径，恢复后重建计数。
- **验收口径**：每次入库/出库后Redis计数与DB空闲袋数一致；人为制造偏差后≤30分钟被对账修正并告警；对账期间取袋请求按设计短暂重试而非错误扣减。

**FR-M4-19｜状态机统一校验与流转日志**　`P0`　角色：站点管理员、平台管理员　来源：设计书3.2/3.3；任务书工作内容⑥

- **需求描述**：M4全部袋状态变更统一经后端状态机校验，仅允许注册的合法转移；非法跳变拒绝（4102）并记审计，每次成功转移写入流转日志。
- **输入 → 输出**：袋码、事件、操作人上下文、clientRequestId → 状态变更结果与流转日志
- **处理要点**：转移注册表查找(当前态,事件)，未注册即拒（4102）；事务内条件UPDATE（WHERE status=前态 AND version）作并发兜底；成功写bag_transfer_log。
- **验收口径**：非法跳变（如空闲→可复用）报4102、状态不变并留审计；对同一袋并发发起两笔合法转移仅一笔成功；每次成功转移新增一条流转日志。

**FR-M4-20｜M4写操作幂等**　`P1`　角色：站点管理员、平台管理员　来源：设计书9.6/3.3/5.4

- **需求描述**：M4写操作统一携带clientRequestId幂等头，重复提交返回首次结果且不重复流转；批量接口按clientRequestId+袋码逐袋幂等。
- **输入 → 输出**：clientRequestId、袋码 → 首次处理结果
- **处理要点**：Redis幂等键去重（TTL 10分钟），命中已完成的直接返回首次结果；批量逐袋判重；Redis故障时由唯一键兜底。
- **验收口径**：同一clientRequestId重复提交同一袋仅产生一次状态转移与一条流转日志；批量提交中重复出现的袋被单独判重、其余袋正常处理；缺少幂等头的写请求被拒绝。

**FR-M4-21｜M4接口数据权限与越权拦截**　`P0`　角色：普通用户、站点管理员、平台管理员　来源：设计书4.4/9.3；任务书工作内容⑥

- **需求描述**：M4接口按角色与事件上下文站点做数据权限校验：站点管理员限本站，平台管理员可全站代操作；按袋码操作接口在服务层二次校验归属。
- **输入 → 输出**：操作人角色、站点、袋归属 → 放行或2001/2002拒绝
- **处理要点**：拦截器角色校验（2001）+服务层归属比对（2002）；代操作在日志标记；越权尝试写入审计日志。
- **验收口径**：普通用户调用任一M4接口报2001；站点管理员操作他站袋报2002且袋状态不变；越权尝试可在审计日志中查到。

**FR-M4-22｜关键操作审计留痕**　`P1`　角色：站点管理员、平台管理员　来源：设计书7.6；任务书工作内容③⑥

- **需求描述**：消毒登记、报废、状态修正与状态机拒绝（4102）等关键事件写入操作审计日志，含操作人、角色、IP、模块/动作、脱敏入参与结果。
- **输入 → 输出**：操作上下文、动作、结果 → 审计日志记录
- **处理要点**：@AuditLog注解经AOP采集；敏感字段脱敏后记录；异步落库、队列饱和时关键事件同步写；审计表仅授予INSERT/SELECT。
- **验收口径**：完成一次消毒登记、报废、状态修正与一次非法跳变后，审计日志可查得四类记录且入参已脱敏；系统不提供审计记录的修改或删除接口。

**FR-M4-23｜库存变更实时推送**　`P1`　角色：站点管理员、平台管理员　来源：设计书7.3/3.2；任务书工作内容⑥

- **需求描述**：激活上架、上架入库、未使用回收、报废等改变站点库存的转移在事务提交后向库存主题推送变更，站点工作台实时刷新库存数值。
- **输入 → 输出**：转移事件、站点 → WebSocket库存变更消息
- **处理要点**：事务提交后推送WebSocket库存主题（提交前不推）；前端断线指数退避重连并重拉数据兜底；推送失败不影响主事务。
- **验收口径**：执行激活上架后本站在线工作台收到库存变更推送，显示数值与DB空闲袋数一致；断线重连后重新拉取得到一致数据。

**FR-M4-24｜扫码识别袋码与手输兜底**　`P1`　角色：站点管理员、平台管理员　来源：设计书10.3/7.4/9.4；任务书工作内容④

- **需求描述**：站点端在激活上架、出入库、消毒登记、维修报废等操作中支持扫码识别袋码：优先BarcodeDetector、降级jsQR，扫码枪输入等价回车，并提供手输袋码兜底。
- **输入 → 输出**：摄像头/扫码枪/手输袋码 → 通过校验的袋码
- **处理要点**：扫码结果先做格式与校验位校验；码不存在报4106；未激活或不可用报4107并提示激活流程；扫码枪与手输等价进入后续操作。
- **验收口径**：摄像头扫码、扫码枪、手输三种方式均可提交同一袋码进入后续操作；不支持BarcodeDetector的浏览器可降级jsQR识别；非法码报4106、未激活袋报4107并提示激活流程。

### 4.6 快递订单管理（M5）

**FR-M5-01｜申领建单生成订单**　`P0`　角色：普通用户　来源：任务书③；设计书 3.6/5.2/7.2

- **需求描述**：用户扫码申领成功后系统自动生成快递订单，初始状态为待寄件，绑定用户、袋码与取袋站点并返回订单号；该订单作为后续寄件、归还、回收确认与遗失处理的业务凭据。
- **输入 → 输出**：袋码、用户身份凭据 → 订单号、订单状态、袋状态
- **处理要点**：Redis 预扣与袋状态校验通过后，同一事务内建单（待寄件）、袋转已分配并写流转日志；建单失败按补偿路径回退库存与计数。

- **需求描述**：回收确认（含跨站与未标记直投）、遗失确认、超时取消与状态机拒绝等订单关键事件必须写入审计日志，记录操作人、IP、模块、动作、结果与耗时，供平台管理员查询追溯。
- **输入 → 输出**：事件上下文、操作人身份 → 审计日志记录
- **处理要点**：注解式切面采集后异步落库；越权拦截与状态机拒绝另记审计；审计日志仅可查询不可修改删除。
- **验收口径**：执行回收确认与遗失确认后审计日志存在对应记录且含操作人与结果；状态机拒绝产生审计记录；普通用户查询审计日志被拒。

### 4.7 后台管理与数据统计（M6）

- **需求描述**：平台管理员获取数据看板汇总：全平台在用袋数、各状态分布、今日取/还数量与预警站点数，四类指标实时聚合供 KPI 卡展示。

- **处理要点**：按统一口径聚合：在用袋数取状态∈{已分配、使用中、回收在途、待消毒、可复用}；今日取/还按 stats:today:{stationId} 求和；预警站点数取可用库存低于阈值站点数。

**FR-M6-02｜订单趋势统计**　`P0`　角色：平台管理员　来源：设计书 5.6 / 10.2；任务书③④

**FR-M6-03｜快递袋周转率统计**　`P0`　角色：平台管理员　来源：设计书 5.6 / 3.5；任务书③④

- **输入 → 输出**：统计周期、站点（可选） → 周转率数值（按站点/全平台）
- **处理要点**：在循环袋数=非报废、非遗失状态的袋数（含各站点与在途）；按周期与站点分组聚合；口径以 3.5 时限与计数口径表为唯一定义。
- **验收口径**：构造已知数据，接口周转率等于口径公式手算值（含在循环袋数均值）；按站点分组数与站点数一致。

**FR-M6-04｜库存分布统计**　`P0`　角色：平台管理员　来源：设计书 5.6 / 10.2；任务书③④

- **需求描述**：按站点与状态两个维度统计在册袋分布，输出饼图数据，覆盖全部 11 种袋状态枚举。

- **处理要点**：以 bag 表 (station_id,status) 组合索引实时聚合；支持全平台与单站点视图；状态维度覆盖未激活至报废全部枚举。
- **验收口径**：各状态分片值之和等于在册袋总数；抽查单站点数值与 bag 表聚合一致。

**FR-M6-05｜数据看板 ECharts 呈现**　`P0`　角色：平台管理员　来源：设计书 10.2 / 10.5 / 5.6；任务书④

- **输入 → 输出**：统计接口返回数据 → 看板页面（KPI 卡+三类图表）

**FR-M6-06｜操作日志审计查询**　`P0`　角色：平台管理员　来源：设计书 5.6 / 7.6 / 9.5；任务书③⑥

- **需求描述**：平台管理员分页查询操作日志，支持按操作人、模块、时间区间筛选，返回角色、IP、UA、模块动作、脱敏入参、结果与耗时。
- **输入 → 输出**：操作人、模块、时间区间、页码页大小 → 审计日志分页列表
- **处理要点**：仅平台管理员可访问；pageSize 默认 10 最大 100，排序字段白名单；审计数据只读，接口层不提供修改删除。
- **验收口径**：执行一次写操作后可查到对应记录；非平台管理员调用返回 403；密码、手机号在入参中已脱敏。

**FR-M6-07｜登录日志查询**　`P0`　角色：平台管理员　来源：设计书 5.6 / 9.2 / 7.6；任务书③⑥

- **需求描述**：平台管理员分页查询登录日志，覆盖成功与失败记录，含账号、IP、UA、结果、失败原因与时间，支持按账号/时间筛选。
- **输入 → 输出**：账号、时间区间、页码页大小 → 登录日志分页列表
- **处理要点**：登录成功与失败均由认证模块写入 login_log；查询接口仅平台管理员可用；失败原因用于锁定与异常登录排查。
- **验收口径**：制造一次成功与一次失败登录后，日志中两条记录均在且结果标记正确；筛选条件生效。

**FR-M6-08｜关键事件审计与饱和兜底**　`P0`　角色：平台管理员、站点管理员　来源：设计书 7.6 / 9.1；任务书③⑥

- **需求描述**：登录失败、越权拦截、状态机拒绝、报废、状态修正、回收确认（含跨站与未标记直投）等关键事件必须留痕，写入高峰不得静默丢失。

- **处理要点**：@AuditLog AOP 采集操作人、角色、IP、UA、模块动作、脱敏入参、结果（错误码）与耗时后异步落库；队列饱和时关键事件降级同步写、普通事件转应急文件并累加丢弃计数器。
- **验收口径**：逐类触发关键事件后均可查询到审计记录；模拟队列饱和后关键事件不丢失、丢弃计数递增并在看板告警。

**FR-M6-09｜审计数据防篡改与留存**　`P0`　角色：平台管理员　来源：设计书 7.6 / 9.1 / 11.3

- **需求描述**：审计与登录日志应用层不提供修改、删除接口；数据库账号对审计相关表仅授予 INSERT、SELECT，写入后不可变更。
- **输入 → 输出**：无 → 不可变更的审计数据
- **处理要点**：数据库层最小权限授权；保留期≥180 天；随备份加密存储，调取登记、到期销毁。
- **验收口径**：接口清单中无审计修改/删除入口；应用账号执行 UPDATE/DELETE 审计表被拒；留存配置≥180 天。

**FR-M6-10｜库存预警与调度参考**　`P0`　角色：平台管理员　来源：设计书 5.3 / 3.4.3 / 5.6；任务书③④

- **需求描述**：看板展示可用库存低于预警阈值的站点及其当前库存与阈值，作为平台管理员创建调拨（富余站→预警站）的决策依据。
- **输入 → 输出**：站点预警阈值、可用库存 → 预警站点列表、预警站点数
- **处理要点**：取站点 warn_threshold 与可用库存比对生成预警清单；预警站点数计入看板汇总；调拨创建复用 M3 接口并锁定明细袋。
- **验收口径**：站点可用库存低于阈值时出现在预警列表且库存与阈值可读；预警站点数与汇总指标数值一致。

**FR-M6-11｜异常与风控告警清单**　`P1`　角色：平台管理员　来源：设计书3.5、7.5、9.1；任务书③

- **需求描述**：将取消后 48h 袋仍已分配、回收在途 72h 未确认、调拨出库 48h 未核收、寄件后 7 天超时未归还等异常，及同类高频确认等风控线索纳入看板告警。
- **输入 → 输出**：定时扫描标记结果 → 看板告警清单
- **处理要点**：按设计书7.5频率：超时订单扫描每5分钟（24h未寄件、7天超时、取消后48h未收回）；回收/调拨超时扫描每15分钟（回收在途72h、调拨48h）；命中项入告警清单可跳转处置。
- **验收口径**：构造回收在途72h未确认记录，经15分钟扫描任务后清单出现该单并可跳转处置；取消后48h未回收记录经5分钟任务入清单；高频确认超阈值出现风控告警条目。

**FR-M6-12｜平台看板实时推送**　`P1`　角色：平台管理员　来源：设计书 7.3 / 5.6；任务书⑥

- **需求描述**：平台管理员经 WebSocket 订阅 platform/dashboard 主题，实时接收全局库存与订单异动、预警触发消息并刷新看板。
- **输入 → 输出**：WebSocket 订阅请求（首帧 JWT） → 库存/订单异动、预警推送消息
- **处理要点**：首帧鉴权通过方可订阅；服务端按角色生成订阅白名单，越权订阅拒绝并审计；事务提交后推送；30s 心跳复检失效即断开。
- **验收口径**：平台管理员订阅后可收到申领导致的库存变更消息；普通用户订阅被拒；被禁用账号在心跳周期内断开。

**FR-M6-13｜全平台总台账集中查询**　`P1`　角色：平台管理员、站点管理员　来源：设计书 2.5 / 4.4 / 5.1 / 5.4 / 5.5；任务书②④

- **需求描述**：平台管理员可在后台集中查询全平台用户、站点、快递袋与订单台账并跳转详情，查询范围不受站点限制。
- **输入 → 输出**：台账类型、筛选条件、页码页大小 → 全平台台账分页列表
- **处理要点**：复用 M1/M3/M4/M5 台账查询接口，平台管理员角色放行；分页与筛选参数统一（pageNum/pageSize/时间区间/排序白名单）。
- **验收口径**：平台管理员查袋台账返回全部站点数据；站点管理员仅本站；普通用户调用被 403 拦截。

**FR-M6-14｜日统计汇总任务**　`P2`　角色：平台管理员　来源：设计书 7.5 / 8.2 / 5.6

- **需求描述**：每日 01:00 汇总订单量、周转率与库存分布写入 stats_daily（全平台与各站点），作为看板可选加速数据源。
- **输入 → 输出**：无（定时触发） → stats_daily 日汇总记录
- **处理要点**：幂等键 (date, station_id) 唯一，station_id=0 表示全平台；独立调度线程池执行，声明执行超时与失败告警。
- **验收口径**：手动触发后 stats_daily 生成当日记录且重复执行不产生重复行；汇总值与实时聚合接口一致。

## 5 用例描述

本章给出 20 个核心用例的详细描述。用例编号规则见 1.5：`UC-U` 用户端、`UC-S` 站点端、`UC-P` 平台端。

> **说明**：主流程为顺利路径，备选流覆盖失败路径与补偿处理。两条约定贯穿全部用例——① 袋状态是权威事实，订单状态跟随联动，任何一方都不允许被单独修改；② 回收确认是权威动作，用户"标记归还"只是可选辅助，未标记直投同样可以完成回收。

### 5.1 用户端用例

#### UC-U01 扫码取袋

- **参与者**：普通用户
- **目标**：扫描快递袋二维码申领一只空闲袋，生成待寄件订单并预占站点库存。
- **前置条件**：用户已登录且账号未被禁用（JWT 有效）；袋贴有可识别二维码（可扫码/手输/扫码枪）；站点可用库存计数已初始化（否则 5102 重试）
- **后置条件**：成功：生成待寄件订单，袋为已分配，站点库存 −1 并推送。；成功：未归还计数 +1、日频次 +1，预扣凭据与流转日志已写。；失败：Lua 原子不落账或经 R0 补偿回退，双防线保证无超发漏发。
- **关联需求**：FR-M2-01、FR-M2-02、FR-M2-03、FR-M2-04、FR-M5-01

**主流程**

1. 用户：手机扫描袋上二维码（或手输袋码，扫码枪输入等价回车）。
2. 系统：校验袋码格式与存在性，返回规格、可否领用与所在站点（最小必要集）。
3. 用户：核对袋与站点信息，点击“确认申领”（携带 clientRequestId）。
4. 系统：校验袋状态为空闲且未被未出库调拨单锁定。
5. 系统：Redis Lua 原子校验未归还<3、日频次<10 并扣库存、写 25h 预扣凭据。
6. 系统：事务建订单（待寄件）、袋条件更新为已分配（事件#2）、写流转日志。
7. 系统：提交后推送站点库存变更，返回订单号与 24h 内寄件时限。
8. 用户：记录订单号，进入寄件表单，在 24h 内登记寄件信息。

**备选流**

- 2 袋码不存在 → 返回 4106 提示核对；1 分钟内 ≥10 次查询失败触发 5101 限流并审计。
- 2 袋未激活/报废/遗失等不可用 → 返回 4107，提示不可领用（未激活引导激活）。
- 4 袋已被并发申领、状态非空闲 → 返回 4107 当前不可用，提示重扫其它袋。
- 5 未归还订单已达 3 单 → Lua 返回 -3，拒绝（4104），库存不扣、不建单。
- 5 当日取袋已达 10 次 → Lua 返回 -4，拒绝并提示次日再试（4109）。
- 5 站点库存不足 → Lua 返回 0，返回 4101，库存与计数均不变化。
- 5 计数初始化中/对账期 → 5102（-1）可重试；-2 按 200ms 退避重试 3 次。
- 6 两笔并发申领同一袋 → DB 条件更新仅一方成功，失败方返回 4103。
- 6 Lua 成功但建单事务失败 → R0 补偿：回补库存、删凭据、计数−1（幂等键 clientRequestId）。
- 3 重复提交同一 clientRequestId → 幂等去重，返回首次申领结果。

#### UC-U02 寄件登记

- **参与者**：普通用户
- **目标**：在申领后 24 小时内登记快递公司与运单号，订单与袋转入使用中。
- **前置条件**：存在本人待寄件订单且未超过 24 小时申领时限；袋实物仍在用户手上，未送回站点；运单信息由用户手工录入（不对接第三方物流）
- **后置条件**：成功：订单与袋同为使用中，预扣凭据删除、流转日志已写。；成功：收件人手机号仅存掩码与哈希；状态变更已推送。；失败：事务回滚，订单/袋状态与预扣凭据均保持原样。
- **关联需求**：FR-M2-05、FR-M5-03、FR-M5-02、FR-M5-10、FR-M5-19

**主流程**

1. 用户：在“我的订单”打开待寄件订单的寄件表单。
2. 用户：填写快递公司、运单号、收件人手机号并提交（带 clientRequestId）。
3. 系统：校验订单归属与状态=待寄件；非本人 2002、非待寄件 4105。
4. 系统：校验参数格式（运单号 8–20 位、手机号 11 位），失败返回 3001。
5. 系统：校验快递公司+运单号联合唯一，防重复运单。
6. 系统：事务内订单→使用中、袋已分配→使用中（事件#3）、写流转日志。
7. 系统：删除 Redis 预扣凭据；库存不回补（实物在用户手上）。
8. 系统：收件人手机号转掩码与带盐哈希落库，不存明文（FR-M5-19）。
9. 系统：推送订单变更；页面展示归还指引与超时规则提示。
10. 用户：等待收件方签收后按指引将袋投放站点回收箱。

**备选流**

- 3 订单不存在 → 4106；存在但非本人 → 2002（先存在性后归属）。
- 3 订单已被撤回或 24h 超时自动取消 → 4105，提示不可寄件、袋须归还。
- 4 运单号/手机号格式非法 → 400+3001，前端表单红字定位错误项。
- 5 运单号已被登记 → 拒绝提交，提示更换运单号（联合唯一）。
- 6 站点同期回收该袋（#5）→ 条件更新冲突仅一方成功，提示状态已变更。
- 6 重复提交同一 clientRequestId → 幂等返回首次结果（TTL 10min）。
- 2 距申领超 24h 已被定时取消 → 表单置灰，提示送回袋后重新取袋。
- 10 寄件后 7 天未归还 → 置超时标记并推送提醒（FR-M5-10，详见 UC-U05）。

#### UC-U03 标记归还

- **参与者**：普通用户
- **目标**：投放站点回收箱后标记归还，订单转待回收确认并通知站点核查。
- **前置条件**：本人存在使用中的订单，且袋仍在流通（未遗失）；投放站点未停用，且实物已投入该站点回收箱
- **后置条件**：成功：订单=待回收确认、袋=回收在途，return_station_id 已记录。；成功：站点收到回收待办；库存与计数在扫码确认前不变。；失败：订单与袋状态不变，可稍后重试标记。
- **关联需求**：FR-M2-06、FR-M5-05、FR-M2-10、FR-M5-12、FR-M5-20

**主流程**

1. 用户：在使用中订单详情点击“标记归还”（可选辅助操作）。
2. 用户：从站点列表选择投放站点并确认提交（带 clientRequestId）。
3. 系统：校验订单归属与状态；非本人 2002、非使用中 4105。
4. 系统：袋使用中→回收在途（事件#6），订单→待回收确认，写流转日志。
5. 系统：订单记录 return_station_id；不改变袋归属 station_id。
6. 系统：向投放站点推送回收待办，向用户推送订单状态变更。
7. 系统：提示以站点扫码确认为准；24h 未确认提醒、72h 入异常清单。
8. 用户：等待站点管理员扫码确认，期间持续跟踪订单状态。

**备选流**

- 1 用户未标记直接投放 → 站点扫码仍可直投确认（#7/#8），不得拒绝回收。
- 2 投放站点已停用 → 列表不展示（nearby 过滤），提示换选站点。
- 3 状态不可用（待寄件/已完成等）→ 4105 提示当前状态不可标记归还。
- 4 站点同期扫码确认 → 条件更新冲突，一方提示订单已完成或状态已变更。
- 7 标记后 24h 站点未确认 → 系统提醒站点；用户订单保持待回收确认。
- 7 标记后 72h 未确认 → 纳入异常清单，平台管理员核实后可按 #18 确认遗失。
- 6 推送未达（用户离线）→ 重连后重新拉取订单兜底，无消息重放。

#### UC-U04 撤回申领

- **参与者**：普通用户
- **目标**：对未寄件的待寄件订单撤回取消，释放未归还计数，袋交由站点收回。
- **前置条件**：本人存在待寄件订单（已申领未寄件）；袋尚未被站点未使用回收（#4）或回收确认（#5）处理
- **后置条件**：成功：订单=已取消，未归还计数 −1，预扣凭据已删除。；成功：袋保持已分配，待站点 #4（回空闲）或 #5（待消毒）收回。；失败：订单状态与计数不变，无部分更新。
- **关联需求**：FR-M2-07、FR-M5-04、FR-M5-09、FR-M5-11、FR-M5-13、FR-M2-03

**主流程**

1. 用户：在“我的订单”对待寄件订单点击“撤回申领”。
2. 用户：确认撤回；提示撤回不受 24h 时限，日频次不退还、袋须送回站点。
3. 系统：校验订单归属与状态；非本人 2002、非待寄件 4105。
4. 系统：订单置已取消（原因=用户撤回），未归还计数 −1。
5. 系统：删除预扣凭据；不回补库存（实物仍在用户手上）。
6. 系统：袋保持已分配（订单级操作不改袋状态）。
7. 系统：推送取消结果，提示送回站点；站点扫码自动路由 #4/#5。
8. 用户：将袋投放回收箱或交回柜台，待站点扫码收回。

**备选流**

- 3 订单已使用中 → 4105 拒绝撤回，引导改用标记归还。
- 3 订单已取消/已完成/已遗失 → 幂等返回现状，不重复置位与扣减。
- 4 撤回不受 24h 限制；与 24h 自动取消并发 → 谁先置取消，计数只减一次。
- 7 取消后 48h 袋仍已分配 → 异常看板告警，提醒站点管理员处理。
- 7 取消后满 7 天仍未回收 → 平台管理员可按 #18 确认遗失，责任人=申领用户。
- 2 撤回消耗的日频次不退 → 当日再取袋仍受 10 次上限约束（4109）。

#### UC-U05 查询我的订单

- **参与者**：普通用户
- **目标**：分页查询本人订单与详情，识别超时提醒，据此归还或处理异常。
- **前置条件**：用户已登录（JWT 有效），存在历史或进行中订单
- **后置条件**：成功：返回本人订单分页与详情，超时标记与提醒可见。；安全：全程 user_id 强制过滤，手机号等敏感字段脱敏。；无副作用：查询不改变任何订单与袋状态。
- **关联需求**：FR-M2-08、FR-M5-16、FR-M2-09、FR-M5-19、FR-M1-18、FR-M1-06

**主流程**

1. 用户：打开“我的订单”页面（移动端卡片列表）。
2. 系统：强制 user_id=当前 uid 过滤，分页返回本人订单。
3. 用户：按状态筛选或翻页（待寄件/使用中/待回收确认/已完成/已取消/已遗失）。
4. 系统：展示订单号、袋码、状态与时间线；手机号仅掩码显示。
5. 用户：点击订单查看详情（袋状态、归还站点、流转节点）。
6. 系统：对寄件后 7 天未归还订单显示超时标记，并推送提醒。
7. 用户：依据提醒执行标记归还或联系站点/平台处理。
8. 系统：状态变更经 WebSocket 推送；断线重连重新拉取兜底。

**备选流**

- 5 订单不存在 → 4106；存在但非本人 → 2002（先存在性后归属）。
- 2 token 失效（jti 黑名单/token_version 吊销或 2h 到期）→ 401 跳登录保留回跳；<30min 静默续签。
- 6 待寄件超 24h → 显示已自动取消与重新取袋引导（袋先送回站点）。
- 6 寄件后 ≥14 天未归还 → 订单可能被平台确认已遗失，显示责任提示。
- 4 无订单或筛选无结果 → 空态引导扫码取袋。
- 6 站点已回收但推送未达 → 下拉刷新重新拉取状态兜底。

### 5.2 站点端用例

#### UC-S01 回收确认

- **参与者**：站点管理员
- **目标**：扫码确认回收箱内快递袋，按绑定订单状态四路路由，完成回收并联动订单闭环。
- **前置条件**：站点管理员已登录，JWT 绑定本站；袋实物已投放本站回收箱，状态∈{使用中, 回收在途, 已分配}；扫码设备可用（扫码枪或移动端扫码）；写操作携带 clientRequestId 幂等头
- **后置条件**：路由②③④：袋→待消毒、归属改确认站点；路由①：袋回空闲并库存+1。；订单按路由闭环：已完成（#7/#8）或已取消（#5）；#4 时订单已闭环。；#5 计数−1；#7/#8 计数−1 且 use_count+1。；回收/入库记录、流转日志与审计已写入。
- **关联需求**：FR-M3-08、FR-M3-09、FR-M3-10、FR-M5-06、FR-M5-07、FR-M4-09

**主流程**

1. 站点管理员：打开回收箱待确认清单（含未标记直投袋），清点并逐只扫码
2. 系统：校验操作人站点=回收箱所属站点，不比对袋的旧归属
3. 系统：按绑定订单状态自动路由四路（#4/#5/#7/#8），逐只前置校验
4. 系统：路由①订单已取消/不存在且袋已分配 → #4：袋回空闲、库存+1、订单闭环
5. 系统：路由②订单仍待寄件（未使用袋）→ #5：袋→待消毒、订单→已取消、计数−1
6. 系统：路由③订单使用中（含未标记直投）→ #7：袋→待消毒、订单→已完成
7. 系统：路由④订单待回收确认 → #8：同 #7；#7/#8 另计 use_count+1、计数−1
8. 系统：事务内条件更新：#5/#7/#8 的袋 station_id 改为确认站点，#4 保持原归属
9. 系统：写回收/入库记录与流转日志，逐只返回结果明细并推送库存、订单主题
10. 站点管理员：按逐袋结果处理失败项（重扫核对或留待下次批量处理）

**备选流**

- 2a 袋旧归属≠本站（跨站归还）→ 允许确认，确认前不校验旧归属，归属在事务内改本站
- 3a 袋=使用中且订单=使用中（未标记直投）→ 按 #7 路由，不得因未标记拒绝回收
- 3b 袋=回收在途且订单=待回收确认 → 按 #8 路由，其余同 #7
- 3c 袋=已分配且订单=待寄件 → 按 #5 路由：订单→已取消、袋→待消毒、计数−1
- 3d 袋=已分配且订单已取消/不存在 → 按 #4 路由：袋回空闲、库存+1、订单闭环
- 3e 袋为未激活/报废/已遗失等不可用态 → 该袋失败返回 4107 或 4102，其余继续
- 1a 扫码失败或袋码不存在 → 该袋返回 4106，提示手工输码核对，不落账
- 4a 条件更新影响行数=0（重复扫描）→ 该袋返回 4103/4105，提示已确认，不重复计数
- 1b 同一 clientRequestId 重复提交 → 幂等返回首次逐袋结果，不重复流转
- 4b 该袋原在异常清单（回收在途≥72h）→ 确认成功后自动移出，告警消除
- 6a Redis 计数回退失败 → 记 ERROR 告警，由每日 02:00 计数对账按 DB 纠偏

#### UC-S02 未使用回收

- **参与者**：站点管理员
- **目标**：收回申领后未使用的袋，解除预扣并回补本站可用库存。
- **前置条件**：站点管理员已登录并绑定本站；袋实物在本站未离站，状态=已分配；绑定订单已取消或不存在；写操作携带 clientRequestId 幂等头
- **后置条件**：袋→空闲并计入本站可用库存；订单保持已取消，预扣凭据失效；回收记录、流转日志与审计已写入
- **关联需求**：FR-M4-09、FR-M5-08、FR-M5-13、FR-M4-18、FR-M4-20、FR-M4-21

**主流程**

1. 站点管理员：核对本站“已分配”袋实物，扫袋码发起未使用回收
2. 系统：校验袋归属本站、状态=已分配
3. 系统：确认绑定订单已取消或不存在（撤回或 24h 超时来源）
4. 系统：事务内执行转移#4（已分配→空闲），条件更新防并发
5. 系统：写未使用回收记录与流转日志
6. 系统：Redis 本站可用库存+1，提交后推送库存主题
7. 系统：提示袋已回空闲，可再次被申领

**备选流**

- 3a 绑定订单仍为待寄件 → 拒绝#4，自动路由#5：订单→已取消、袋→待消毒、计数−1
- 3b 订单取消后超 48h 未处理 → 该袋已在异常看板告警，本次处理自动消除告警
- 2a 袋状态非已分配（如回收在途）→ 该袋返回4102，提示改用回收确认
- 2b 袋归属非本站 → 返回2002，提示至归属站点办理
- 4a 条件更新0行（并发处理）→ 返回4103，提示已被处理，不重复回补
- 6a Redis 回补失败或降级中 → 先落库，记补偿日志，由 30 分钟对账（R4）纠正
- 1a 同一 clientRequestId 重复提交 → 幂等命中，库存仅回补一次

#### UC-S03 激活上架

- **参与者**：站点管理员
- **目标**：核验新到站袋并激活上架，纳入本站可申领库存。
- **前置条件**：站点管理员已登录并绑定本站；袋状态=未激活，登记站点=本站，档案完整；实物到站，二维码已打印待贴标；写操作携带 clientRequestId 幂等头
- **后置条件**：袋→空闲，计入本站可用库存并可申领；入库记录、流转日志与审计已写入；库存主题已推送，各端视图同步
- **关联需求**：FR-M4-07、FR-M4-19、FR-M4-24、FR-M4-18、FR-M4-23、FR-M3-20

**主流程**

1. 站点管理员：对到站新袋做外观核验，打印并粘贴二维码标签
2. 站点管理员：扫描袋码，发起激活上架
3. 系统：校验状态=未激活、登记站点=操作人站点、校验位通过
4. 系统：要求确认实物与袋码核对一致后方可提交
5. 系统：事务内执行转移#1（未激活→空闲），写入库记录与日志
6. 系统：Redis 本站库存+1，提交后推送库存主题
7. 系统：返回结果，袋进入可申领状态

**备选流**

- 3a 校验位不符或袋码不存在 → 返回4106，提示手工输码或重贴标签
- 3b 袋非本站登记或状态≠未激活 → 返回2002/4102，提示归属站点或已激活
- 3c 登记站点已停用 → 拒绝激活返回4105，提示停用站不可上架
- 4a 实物与码不一致（疑换贴）→ 终止激活并登记异常，转审计线索
- 5a 条件更新0行（并发激活）→ 返回4103，提示已被激活，不重复+1
- 6a Redis 不可用（降级中）→ 以 DB 落库为准，恢复后按初始化流程重建计数
- 2a 同一 clientRequestId 重复提交 → 幂等返回首次结果，库存不重复+1

#### UC-S04 出入库登记

- **参与者**：站点管理员
- **目标**：可复用袋上架入库、报废与差异袋实物出库全程登记，账实一致。
- **前置条件**：站点管理员已登录并绑定本站；入库袋状态=可复用且 use_count 未超上限；出库袋为报废袋或持批准的盘点差异单；写操作携带 clientRequestId 幂等头
- **后置条件**：入库袋→空闲并计入本站可用库存；出库袋实物离站，出库记录已登记；逐袋结果、流转日志与审计已写入
- **关联需求**：FR-M4-08、FR-M4-10、FR-M4-18、FR-M4-19、FR-M4-20、FR-M4-23

**主流程**

1. 站点管理员：选择上架入库，扫描或勾选本站可复用袋批量提交
2. 系统：逐只校验归属本站、状态=可复用、use_count<上限
3. 系统：逐只执行#11（可复用→空闲），写入库记录与流转日志
4. 系统：Redis 本站库存+N，提交后推送库存主题
5. 站点管理员：选择出库登记，扫描报废袋或差异批准袋并提交
6. 系统：校验出库事由（报废移交/批准差异）与袋当前状态
7. 系统：写出库记录，登记实物离站（不重复扣减库存）
8. 系统：返回逐袋结果明细（成功或失败+错误码）

**备选流**

- 2a use_count≥上限（默认50）→ 拒绝该袋返回4108，提示转维修或报废
- 2b 袋状态非可复用（如待消毒）→ 该袋返回4102，提示先完成消毒
- 2c 袋归属非本站 → 返回2002，提示至归属站点办理
- 3a 条件更新0行（并发上架）→ 该袋返回4103，其余袋继续
- 4a Redis 库存+N 失败 → 先落库，记补偿日志，由 30 分钟对账（R4）纠正
- 6a 出库袋非报废且无批准差异单 → 拒绝返回4105，提示补审批凭据
- 6b 维修类袋申请出库 → 引导改走维修接口（repair），不得登记出库
- 1a 同一 clientRequestId 重复提交 → 幂等，库存不重复回补

#### UC-S05 消毒登记

- **目标**：按批次登记消毒结果，合格袋回可复用、不合格袋转维修。
- **前置条件**：站点管理员已登录并绑定本站；袋实物在本站，状态=待消毒；消毒作业已完成，批次信息可追溯；写操作携带 clientRequestId 幂等头
- **后置条件**：合格袋→可复用，等待上架入库；不合格袋→维修中并已登记缺陷说明；消毒记录、流转日志与审计已写入
- **关联需求**：FR-M4-11、FR-M4-12、FR-M4-19、FR-M4-20、FR-M4-22

**主流程**

1. 站点管理员：录入消毒批次信息（批号、方式、时间、操作人）
2. 站点管理员：扫描或勾选本批待消毒袋（≤200只）提交
3. 系统：逐只校验归属本站、状态=待消毒
4. 站点管理员：逐袋录入结果（合格/不合格，不合格填缺陷）
5. 系统：合格袋执行#9（待消毒→可复用），写消毒记录与明细
6. 系统：不合格袋执行#10（待消毒→维修中），并写维修登记
7. 系统：返回逐袋结果明细，单只失败不影响其余

**备选流**

- 3a 袋状态非待消毒 → 该袋返回4102，提示当前状态，其余继续
- 3b 袋归属非本站 → 返回2002，提示至归属站点登记
- 4a 不合格未填缺陷说明 → 拒绝该袋返回3001，要求补充说明
- 2a 批次袋数超 200 上限 → 整批拒绝返回3001，提示拆批提交
- 2b 扫码失败或袋码不存在 → 该袋返回4106，提示手工输码
- 5a 条件更新0行（并发登记）→ 该袋返回4103，不重复写消毒记录
- 1a 同一 clientRequestId 重复提交 → 幂等返回首次逐袋结果

- 2b 袋已在维修中 → 返回4105，不可重复登记
- 2c 袋归属非本站 → 返回2002，提示至归属站点维修
- 3a 前态=空闲且 Redis 库存−1 失败 → 先落库，记补偿日志，由对账（R4）纠正
- 5a 未选择维修结果 → 返回3001，要求选择修复或无法修复

- 6b 无法修复走#14报废 → 写报废记录并列入审计重点核查
- 1a 同一 clientRequestId 重复提交 → 幂等，不重复写记录

- 6a 目标态超出白名单 → 拒绝修正，仅限空闲/维修中/已遗失/报废

**主流程**

1. 站点管理员（源站）：核对调拨单明细，逐只扫袋码提交调拨出库

7. 系统：归属改目标站，目标站 Redis 库存+N，调拨单闭环
8. 系统：返回逐袋结果，两站库存视图同步更新

**备选流**

- 1a 某袋实物缺失或码损 → 平台管理员剔除明细解锁回空闲，其余继续出库
- 2a 单据已完成/已取消 → 拒绝出库返回4105，提示不可再执行
- 2b 袋被其他未出库调拨单锁定 → 该袋失败返回4105，其余袋继续出库
- 6a 核收袋码与明细不一致 → 该袋拒收并登记差异，交平台管理员处理
- 5a 部分核收 → 单据置异常保留差异，平台决定继续核收或终止并解锁明细
- 4a 出库后 48h 未核收 → 定时扫描提示，平台管理员可按#19确认在途遗失
- 3a 源站 Redis 库存−N 失败 → 先落库，记补偿日志，由对账（R4）纠正
- 1b 同一 clientRequestId 重复提交 → 幂等，不重复出库或核收

#### UC-P02 站点维护与停用移交

- **参与者**：平台管理员、站点管理员
- **目标**：维护站点信息，并在停用前校验可用库存为 0 与非终态实物清零或指定接收站，完成实物移交。
- **前置条件**：平台管理员已登录且具备站点管理权限；新增时站点名称不与既有站点重复；编辑时目标站点存在；停用前该站可用库存（空闲袋数）为 0，需先调拨移交；非终态实物（待消毒/可复用/维修中/未激活）可清零或已指定接收站
- **后置条件**：站点信息已保存，或站点已置停用并全程留痕；停用站不再提供取袋与上架入口，实物按移交方案处理；站内袋最终全部处于空闲、调拨在途或报废
- **关联需求**：FR-M3-01、FR-M3-02、FR-M3-04、FR-M3-11、FR-M3-21

**主流程**

1. 平台管理员：新增或编辑站点，填写名称、地址、开放时段与预警阈值
2. 系统：校验参数与名称唯一性，保存站点信息并返回结果
3. 平台管理员：发起站点停用，选择「实物清零」或「指定接收站」方式
4. 系统：校验可用库存为 0（不满足提示先调拨移交），并统计非终态实物数量
5. 系统：前置校验通过后置站点为停用，并记录停用审计日志
6. 系统：该站退出就近站点列表，不再允许取袋与激活上架
7. 站点管理员或平台管理员：对站内剩余袋执行回收确认、消毒、上架或调拨出库
8. 系统：跟踪直至站内袋全部处于空闲、调拨在途或报废，移交完成

**备选流**

- 2a 站点名称与既有站点重复 → 拒绝保存，返回 3001 并提示改名，原记录不受影响
- 4a 可用库存非 0 → 拒绝停用，返回 4105 并提示先调拨移交清零
- 4b 非终态实物大于 0 且未指定接收站 → 拒绝停用，返回 4105 并列出待处理数量
- 7a 停用后回收箱仍有待确认袋或已分配未使用袋 → 由站点管理员或平台管理员代操作收尾
- 7b 平台管理员代操作停用站收尾业务 → 前置校验不变，审计日志标注代操作
- 7c 收尾中发现袋破损无法修复或达复用上限 → 按 #14/#15 报废并单独留痕

#### UC-P03 调拨单创建与跟踪

- **参与者**：平台管理员、站点管理员
- **目标**：依据库存预警创建站间调拨单并锁定明细袋，完成出库与核收闭环，异常单据保留差异记录。
- **前置条件**：平台管理员已登录且具备调拨管理权限；源站与目标站均已启用且不为同一站点；源站有足够空闲袋，预警显示目标站库存低于阈值
- **后置条件**：调拨单按状态机推进：待出库→在途→已完成或异常；袋归属随核收变更为目标站，两站库存增减一致；异常单据保留差异记录与责任线索供追溯
- **关联需求**：FR-M3-11、FR-M3-12、FR-M3-13、FR-M3-14、FR-M3-15、FR-M3-16

**主流程**

1. 平台管理员：查看看板库存分布与预警站点，确定源站、目标站与数量
2. 平台管理员：创建调拨单，逐只扫码将源站空闲袋加入明细（建单即锁定）
3. 系统：校验袋为空闲且未被未出库调拨单引用，锁定明细并置单据待出库
4. 站点管理员（源站）：执行调拨出库，逐只扫码校验袋码与明细一致
5. 系统：执行转移 #16，袋转调拨在途，源站库存 −N，单据转在途
6. 站点管理员（目标站）：货物到达后逐只扫码核收
7. 系统：执行转移 #17，袋回空闲且归属改目标站，目标站库存 +N
8. 系统：全部明细核收后单据置已完成，推送库存变更并留痕

**备选流**

- 2a 所选袋非空闲或已被未出库调拨单锁定 → 拒绝加入明细，返回 4105 提示先释放占用
- 2b 建单后需取消（未出库） → 仅「待出库」允许整单取消并解锁明细回空闲，其他状态拒绝（4105）
- 4a 出库扫码失败（实物缺失或码损） → 剔除该袋明细解锁回空闲，其余明细继续出库
- 5a 出库后 48 小时未核收 → 标记调拨超时并提示，可转入平台在途遗失确认（#19）
- 8a 部分核收后平台决定终止 → 单据置异常并保留差异记录，未出库明细解锁回空闲

#### UC-P04 遗失确认与责任认定

- **参与者**：平台管理员
- **目标**：对超期未还、回收在途超时、取消留置及调拨在途超时的袋确认遗失，认定责任并记录处置结论。
- **前置条件**：平台管理员已登录且具备遗失裁决权限；袋处于使用中、回收在途、已分配或调拨在途等可裁决状态；时限满足：寄件后≥14 天、回收在途≥72h、取消后满 7 天或出库后≥48h 未核收
- **后置条件**：袋置已遗失，订单置已遗失或调拨单置异常，业务闭环；未归还计数：口径①②各−1；口径③不重复扣减；责任记录与审计日志留痕：责任人、结论、裁决人可追溯
- **关联需求**：FR-M5-14、FR-M5-15、FR-M3-16、FR-M5-12、FR-M5-13、FR-M4-15

**主流程**

1. 平台管理员：从超时未归还列表或异常看板打开待裁决异常项
2. 系统：校验时限与袋状态满足 #18/#19 确认遗失的前置条件
3. 平台管理员：认定责任——使用中、回收在途或留置超期归申领用户，调拨在途归源站
4. 系统：执行转移 #18/#19，袋置已遗失并推送相关方
5. 系统：口径①②（订单在三态内）订单转已遗失、未归还计数−1
6. 系统：口径③订单已取消（取消时已减过）→ 订单保持已取消，不重复扣减计数
7. 系统：调拨在途口径关联调拨单置异常；写责任记录（单号、责任人、结论、裁决留痕）
8. 系统：写审计日志并列入重点核查，同步更新异常清单与看板口径

**备选流**

- 1a 核查期间袋已被站点回收确认或未使用回收 → 异常项自动消除，无需执行遗失确认
- 2a 时限未满足 → 拒绝确认遗失，返回 4105 并提示该袋最早可裁决时间
- 3a 责任主体暂无法确定 → 责任人留空记为「责任待定」，处置结论照常留痕
- 4a 确认时袋状态已被其他操作改变 → 状态机拒绝并报 4102，提示刷新异常清单重试
- 6a 确认后该袋被找回 → 平台管理员执行 #20 找回转待消毒，责任记录追加「已找回」注记

#### UC-P05 状态修正（白名单目标态）

- **参与者**：平台管理员、站点管理员
- **目标**：依据盘点差异按 #21 修正个别袋状态，目标态限白名单，按源/目标态计算库存增减并全程留痕。
- **前置条件**：平台管理员已登录且具备状态修正权限；盘点单已提交并生成袋级差异清单；备有盘点差异单号与修正原因，修正袋为非终态
- **后置条件**：差异袋修正为白名单目标态，库存增减与目标态一致；修正写入流转日志与审计日志，列为重点核查项；跨站或联动订单的袋，归属与业务单据同步更新
- **关联需求**：FR-M4-16、FR-M4-17、FR-M4-18、FR-M4-19、FR-M4-22

**主流程**

1. 站点管理员：完成盘点，提交账面数、实际数与袋级差异清单
2. 系统：生成盘点单并自动计算差异，盘点单只可作废不可删除
3. 平台管理员：打开差异明细，选择待修正袋并填写差异单号与原因
4. 平台管理员：选择白名单目标态——空闲、维修中、已遗失或报废
5. 系统：校验目标态、袋状态与差异单号，执行转移 #21（人工修正）
6. 系统：按源/目标态增减库存：源空闲转出 −1，转入空闲 +1，相同不动
7. 系统：跨站修正同步 station_id；报废或遗失联动写记录并处理订单
8. 系统：写流转日志与审计日志，更新盘点单闭环状态并推送库存

**备选流**

- 2a 盘点差异为零 → 盘点单直接闭环，无需执行状态修正
- 3a 未填写盘点差异单号或修正原因 → 返回 3001 字段级提示，拒绝提交
- 4a 目标态不在白名单 → 拒绝修正，返回 4102 并提示合法目标态集合
- 5a 并发冲突：袋已被其他流转改变 → 条件更新影响 0 行，终止并报 4103 提示刷新
- 8a 差异袋尚未全部修正 → 盘点单保持待修正，剩余差异留待后续处置

#### UC-P06 查看看板与审计日志

- **参与者**：平台管理员
- **目标**：通过数据看板掌握运营态势，并查询审计与登录日志，为调度决策与安全核查提供依据。
- **前置条件**：平台管理员已登录且具备统计与审计查看权限；统计口径与审计、登录日志数据已持续写入
- **后置条件**：看板指标与日志查询结果按权限与口径展示；审计数据保持只读、可核查，保留期不少于 180 天；异常线索可转入调拨、裁决或账号处置等后续流程
- **关联需求**：FR-M6-01、FR-M6-02、FR-M6-03、FR-M6-04、FR-M6-06、FR-M6-07

**主流程**

1. 平台管理员：打开数据看板，查看在用袋数、状态分布、今日取还与预警站点数
2. 系统：按口径实时聚合，在用袋数为已分配至可复用各状态之和
3. 平台管理员：按周期或站点切换订单趋势、周转率与库存分布图表
4. 系统：返回趋势折线、周转率柱状与库存分布饼图数据供 ECharts 渲染
5. 平台管理员：进入审计日志页，按操作人、模块与时间筛选查询
6. 系统：分页返回日志明细（动作、脱敏入参、结果、耗时），只读不可改
7. 平台管理员：查询登录日志，核查连续失败、账号锁定等安全事件
8. 平台管理员：发现异常后转入处置——创建调拨、发起遗失裁决或禁用账号

**备选流**

- 1a 普通用户或站点管理员访问看板与审计接口 → 垂直越权拦截，返回 2001 并记审计
- 5a pageSize 超过上限 100 → 返回 3001 参数校验失败，提示按最大 100 分页
- 6a 尝试修改或删除审计记录 → 系统不提供该类接口，库账号仅 INSERT/SELECT，拒绝执行
- 6b 审计异步落库队列饱和 → 关键事件同步落库，普通事件应急文件回放补录并计数告警

## 7 数据需求

### 7.1 数据实体

系统共 **21 张数据表**，按业务域分为六组。完整字段级定义（类型、可空、默认值、索引）见《数据库设计说明书》第 4 章，本节只登记需求侧的数据范围。

| 业务域     | 数据实体                                                                                     | 主要承载需求                     |
| ---------- | -------------------------------------------------------------------------------------------- | -------------------------------- |
| 用户与权限 | `sys_user`、`sys_role`、`sys_user_role`                                                      | FR-M1 全部                       |
| 站点与库存 | `station`、`stock_record`                                                                    | FR-M3-01~07、FR-M3-19            |
| 快递袋     | `bag`、`bag_transfer_log`                                                                    | FR-M4-01~06、FR-M4-19            |
| 订单与责任 | `bag_order`、`liability_record`、`stock_compensation_log`                                    | FR-M5 全部                       |
| 作业单据   | `disinfect_record`、`disinfect_detail`、`repair_record`、`scrap_record`、`inventory_check`、`allocation_order`、`allocation_detail` | FR-M3-11~16、FR-M4-10~17 |
| 审计与统计 | `audit_log`、`login_log`、`stats_daily`、`sys_metric`                                        | FR-M6 全部                       |

另在 Redis 中维护 13 类键（库存计数、预扣凭据、限流计数、幂等键等）。**Redis 不是权威存储**——全部键均可由数据库重建，这是"Redis 故障不导致数据错误"的前提。

### 7.2 数据保留期要求

| 数据类别                       | 保留要求        | 依据                     |
| ------------------------------ | --------------- | ------------------------ |
| 操作审计日志（`audit_log`）    | ≥180 天         | NFR-SEC-06、任务书⑥      |
| 登录日志（`login_log`）        | ≥180 天         | NFR-SEC-06               |
| 应用运行日志                   | 30 天（按天滚动） | NFR-MNT-03             |
| 快递袋流转日志                 | 长期保留        | NFR-REL-05、任务书⑥      |
| 责任认定记录                   | 长期保留        | FR-M5-15                 |
| 业务单据（订单、消毒、调拨等）  | 长期保留        | 追溯需要                 |

超过保留期的审计数据归档导出后清理，**清理操作本身也必须写审计日志**。

### 7.3 数据敏感级别与处理要求

| 级别     | 数据                                                       | 处理要求                                                     |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 绝密     | 用户口令摘要、JWT 密钥、HMAC 密钥                          | 口令仅存 BCrypt 摘要；密钥经环境变量注入，禁止入库、禁止打日志 |
| 机密     | 收件人手机号                                               | **不存明文**，仅存掩码与带盐哈希（FR-M5-19、NFR-SEC-05）      |
| 敏感     | 用户手机号、登录 IP、操作日志中的请求参数                   | 出参一律脱敏；日志落库前完成脱敏                              |
| 内部     | 站点地址、库存数量、订单与袋的业务属性                       | 按角色与数据范围授权访问                                      |
| 可公开   | 站点名称、开放时段                                          | 登录用户可见                                                  |

### 7.4 数据一致性要求

| 编号   | 要求                                                                       | 关联需求              |
| ------ | -------------------------------------------------------------------------- | --------------------- |
| DC-01  | 袋状态为权威事实，订单状态跟随联动，不允许单独修改订单状态                 | FR-M5-02、NFR-REL-05  |
| DC-02  | 每一次袋状态流转必须写流转日志，二者在同一事务内完成                       | FR-M4-19、BR-11       |
| DC-03  | 站点可用库存计数与数据库中该站空闲袋数量一致，每 30 分钟对账纠偏            | FR-M3-19、NFR-REL-02  |
| DC-04  | 同一只袋同一时刻只能绑定一个未完结订单                                     | FR-M2-04、BR-10       |
| DC-05  | 未归还订单计数与订单状态严格同步（进入三态 +1、离开三态 −1），且不得重复扣减 | FR-M5-11、BR-01       |
| DC-06  | 收件人手机号全文不可还原（仅掩码与哈希）                                   | FR-M5-19              |

| 项         | 要求                                                                     | 关联需求          |

| 风格       | RESTful，统一前缀 `/api/v1`，请求与响应均为 JSON                          | NFR-COMPAT-02     |
| 响应结构   | 统一响应体（业务码 + 消息 + 数据），HTTP 状态码只表达传输层语义           | NFR-COMPAT-02     |

### 8.3 错误码要求

系统采用"HTTP 状态码表达传输层语义、业务码表达业务语义"的双层结构。业务错误码统一分配、不得复用，且必须能区分以下类别：参数校验失败、未认证、无权限、资源不存在、资源状态不允许当前操作、并发冲突、限流、依赖不可用（可重试）。完整错误码表见《系统设计说明书》6.4。

**要求**：每条功能需求的"验收口径"中所断言的错误码，必须与错误码表一致；测试用例须逐码验证。

## 9 验收标准

### 9.1 总体验收条件

系统满足以下全部条件方视为通过验收：

1. **闭环可走通**：从新袋入库到再次上架的完整链路（激活上架 → 扫码取袋 → 寄件登记 → 标记归还 → 回收确认 → 消毒登记 → 上架入库）可在真实环境连续走通，且每一步的袋状态与订单状态按状态机口径正确变化。
2. **P0 需求全部通过**：本文档标注 `P0` 的功能需求（共 **53 条**）逐条通过测试。
3. **异常路径可处理**：撤回、24h 超时取消、7 天超时提醒、遗失确认与找回、跨站归还、未标记直投、并发冲突等异常路径均有明确且正确的处理结果。
4. **非功能指标达标**：第 6 章各条 NFR 的量化指标全部满足。
5. **交付物齐备**：源代码与五份文档（需求规格说明书、系统设计说明书、数据库设计说明书、测试报告、用户使用手册）齐备且相互一致。

### 9.2 功能验收方式

| 验收层次 | 方式                                                       | 覆盖范围                     |
| -------- | ---------------------------------------------------------- | ---------------------------- |
| 单元测试 | 对状态机、库存扣减、计数联动等核心逻辑编写单元测试          | 核心服务方法                 |
| 接口测试 | 按第 8 章接口清单逐条执行正向、越权与异常分支用例           | 全部对外接口                 |
| 功能测试 | 按前端页面清单走查全闭环 + 异常路径                         | 三类角色的全部页面           |
| 并发测试 | 多用户并发取袋（库存充足/不足/临界）、对账期间扣减、降级路径 | 库存正确性                   |
| 演示验收 | 现场演示闭环流程与关键异常处置                              | 答辩环节                     |

**逐条验收依据**：每条功能需求的"验收口径"字段即该条的验收判据；测试用例与验收口径一一对应，对应关系在《测试报告》中登记。

### 9.3 非功能验收重点

| 方面     | 验收要点                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 并发正确性 | 500 并发申领 100 只袋，成功数恰为 100，无超发、无漏发、无负库存           |
| 权限       | 三类角色越权访问（水平与垂直）全部被拒绝并记录审计                       |
| 数据保护   | 收件人手机号在数据库与全部接口响应中均不可还原为明文                     |
| 审计完整性 | 报废、状态修正、遗失认定、责任裁决等高风险操作全部留痕且不可篡改         |
| 可用性     | Redis 故障、数据库短暂不可用等场景下系统行为符合降级设计，不产生数据错误 |
