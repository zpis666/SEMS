# SEMS v0.1.1 发布说明

**发布日期：** 2026-10-07
**修订人：** codex+gpt-6.1 sol

## 版本重点

v0.1.1 精简快递袋正常循环状态并移除状态修正时手填盘点单号的要求，同时补强库存初始化互斥、调拨源站归属校验和并发幂等处理。

## 变更内容

- 正常循环状态收敛为“空闲 → 已分配 → 使用中 → 待消毒 → 空闲”。维修中、报废、已遗失、调拨在途等异常及调度扩展状态保留。
- 状态修正请求不再接收 `refCheckNo`，修正原因仍必填；状态修正记录不再写盘点单号。数据库 `bag_transfer_log.ref_check_no` 列保留，供历史流转记录兼容读取，不删除既有审计历史。
- 盘点单仍保留独立业务编号。无差异盘点提交后直接置为 `CLOSED` 并记录闭环时间；有差异时保留待处理状态。差异袋清单只提供人工核验候选，不与状态修正自动关联。
- 调拨建单在袋行锁下校验袋为空闲且当前归属为源站；状态修正等状态变更与调拨建单使用一致的袋行锁和活动调拨引用复核。
- 库存计数重建只有成功取得 `stock:init` 互斥标记后才删除旧计数并重建，避免未取得锁的并发任务清空正在维护的键。
- 幂等完成结果在数据库事务提交后写入 Redis，事务回滚清理处理中占位；相同请求未取得幂等锁时返回可重试错误，Redis 数据访问故障仍按既有降级口径处理。

## 兼容性说明

调用状态修正接口的客户端应移除请求体中的 `refCheckNo`，保留修正原因及目标状态等字段。盘点创建及实物出库所需的独立盘点编号逻辑不受此调整影响。存量 `bag_transfer_log.ref_check_no` 历史数据保留。

## 验证

干净 Maven Wrapper `clean verify` 通过 294 项测试；JaCoCo 行覆盖率为 71.1%（5,459/7,678），状态机包分支覆盖率为 100%。48 项 API 功能检查通过；5 轮真实 MySQL 调拨建单与状态修正并发竞争中，每轮仅一方成功。本次并发测试验证业务正确性，不构成性能压测。详细结果见仓库根目录 `文档/测试报告.md`。
